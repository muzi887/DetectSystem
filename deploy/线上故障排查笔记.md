## 二、数据流（理解后再排查）

```
用户浏览器
  → :88  GET /              → Nginx 直接返回 dist/index.html
  → :88  POST /api/login    → Nginx 反代 → 127.0.0.1:3000/login
```

## 三、常见问题对照表

| 现象 | 真正原因 | 处理 |
|------|----------|------|
| **502** 整站 | 88 端口未放行；或 Nginx/PHP-FPM 异常 | 查防火墙；`curl 127.0.0.1:88` |
| **502** 仅登录/API | Mock 后端未运行；反代目标挂了 | Node 项目是否运行；`curl 127.0.0.1:3000` |
| **404** `/api/...` | **Nginx 反向代理丢失** | 重配 `/api/`、`/api/analysis/`（见下文） |
| **404** AI 识图 | 同上，或 Flask 反代 rewrite 写错 | 见 Nginx 配置章节 |
| PM2 重启次数暴增 | `node_modules` 丢失；`server.js` 有 bug | 用 Node 项目 + `deploy/api_mock` |
| `Cannot find module 'json-server'` | 未 `npm install` 或依赖被清 | 在 api_mock 目录执行 npm install |
| `Cannot access 'db' before initialization` | server.js 在 `let db` 前用了 `db` | 用 `deploy/api_mock/server.js` 覆盖 |
| 本机 curl 88 正常，外网打不开 | **防火墙关了 88**（本次即此情况） | 腾讯云 + 宝塔安全放行 88 |
| `duplicate location "/api/analysis/"` | 配置文件 + 宝塔界面 **重复**加了反代 | 只保留一处（见下文） |

## 四、重要认知（避免误判）

### 1. 半年没动宝塔也会坏

- 服务器重启 → PM2/Node 未自启
- `node_modules` 不在 Git 里，可能被清理
- 老师维护 → **防火墙关端口**、Nginx 反代被覆盖

### 2. 改 `db.json` 不会搞崩网站

- 线上改预警、登录写入数据是 **正常行为**
- 崩溃原因是 **进程 / 依赖 / 防火墙 / Nginx**，不是数据变更

### 3. PHP 项目不用删

- 列表里叫「PHP 项目」，根目录是 `frontend/dist`，本质是 **静态 Vue 站**
- 与 Node 项目（3000）、Python 项目（5000）**并行存在**，互不替代

### 4. 不必用 PM2（推荐 Node 项目）

- 与 `api_flask` 同一种运维方式
- 部署包：`deploy/api_mock/`（`package.json`、`server.js`、`db.json`）
- 详细步骤：`deploy/宝塔部署-不用PM2.md`

## 五、标准恢复流程（网站挂了时）

### Step 1：在服务器本机快速体检

```bash
# 前端
curl -I http://127.0.0.1:88/

# Mock
curl http://127.0.0.1:3000/monitorPoints

# Flask（有响应即可）
curl -I http://127.0.0.1:5000/

# 前端文件是否存在（注意是 dist 不是 disk）
ls /www/wwwroot/DetectSystem/frontend/dist/index.html

# 谁在监听 88
ss -tlnp | grep ':88'
```

| 结果 | 说明 |
|------|------|
| 127.0.0.1:88 ✅，公网 ❌ | **防火墙**，不是代码问题 |
| 127.0.0.1:88 ❌ | Nginx 或站点配置 |
| 3000 ❌ | Node 项目 `api_mock` 未运行或依赖缺失 |
| 88 ✅ 但 /api 404 | **反代丢失** |

### Step 2：防火墙（两处都要）

1. **腾讯云** → 轻量服务器 → **防火墙** → TCP **88** 允许
2. **宝塔** → **安全** → 放行 **88**

> 本机 `curl 公网IP:88` 可能卡住（云厂商 hairpin），以外网手机 4G 测试为准。

### Step 3：恢复 Mock 后端（不用 PM2）

1. PM2 里 **停止并删除** `json-api`（避免占 3000）
2. 上传 `deploy/api_mock/` 的 `package.json`、`server.js` 到服务器  
   - **不要覆盖** 服务器 `db.json`（保留线上数据）除非有意同步
3. 终端：

```bash
cd /www/wwwroot/DetectSystem/api_mock
npm config set registry https://registry.npmjs.org
npm install
node server.js   # 能跑再 Ctrl+C
```

4. 宝塔 → **Node 项目** → 添加/重启 `api_mock`  
   - 路径、启动 `server.js`、端口 3000、Node ≥18  
   - 勾选「不安装 node_module」（已手动 install 时）

**npm 注意**：必须是 `--registry=https://registry.npmjs.org`（有 `=`），否则走坏掉的 npmmirror 会 404。

### Step 4：确认 Python / Node 面板状态

- Node 项目 `api_mock` → 运行中  
- Python 项目 `api_flask` → 运行中  

### Step 5：恢复 Nginx 反向代理

**网站** → `82.157.234.123` → 配置文件，或 **反向代理**（二选一，勿重复）。

推荐写入主配置（Flask **不要** rewrite，json-server **要** rewrite）：

```nginx
# Flask AI（路径保留 /api/analysis/...）
location /api/analysis/ {
    proxy_pass http://127.0.0.1:5000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}

# json-server（/api/login → /login）
location /api/ {
    rewrite ^/api/(.*)$ /$1 break;
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}

location / {
    try_files $uri $uri/ /index.html;
}
```

```bash
nginx -t && nginx -s reload
```

#### duplicate location 报错

- 原因：配置文件里写了 + 宝塔「反向代理」界面也加了  
- 处理：删掉界面里的 `flask_api`/`mock_api`，**或**删掉配置文件里的重复块，只留一处  
- 查找：

```bash
grep -rn "location /api" /www/server/panel/vhost/
grep include /www/server/panel/vhost/nginx/82.157.234.123.conf
cat /www/server/panel/vhost/rewrite/82.157.234.123.conf
```
