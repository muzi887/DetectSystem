# 第一章 系统简介

## 1.1 系统做什么

本系统（简称「青禾智匠」）用于**作物灾害相关的监测、预警与辅助决策**，在一张 Web 页面里完成以下工作：

- 在地图上查看监测点位置与状态（状态机中文显示：正常 / 预警 / 严重 / 离线 / 维护中 / 未知）；
- 查看传感器、无人机、气象、GIS 等分类数据（传感器为 Mock 趋势；无人机/GIS 为真实热力图素材演示）；
- 上传作物图片做病害/灾害分类（调用 Flask 接口，返回识别结果并写入预警列表）；
- 新建、处理、删除预警记录；
- 针对待处理预警查看点位信息与系统给出的处置建议。

系统为 2025–2026 年「挑战杯」大学生创业计划竞赛参赛作品。Web 端由张晓琳（信息工程学院 · 计算机科学与技术）完成从 0 到 1 的搭建与部署；其他成员分工见系统内「关于我们」页。

## 1.2 功能模块一览

| 导航菜单 | 路由 | 主要功能 |
|----------|------|----------|
| 首页 | /home | 监测点数量、待处理预警数、系统状态汇总、最新预警列表、快捷入口 |
| 相关数据 | /related-data | 四类数据源 Tab 切换、折线图/遥感热力图/气象卡片、AI 结论文案、生成简报（模拟下载） |
| 灾害实时监测 | /map | Leaflet 地图、监测点聚类、点位详情、手动触发/标记解决 |
| 智能分析 | /analysis | 上传图片、选择作物与分类、调用分析接口并生成预警 |
| 灾害预警 | /warnings | 预警列表、新建/标记状态/删除 |
| 智慧决策 | /decision | 待处理预警列表、小地图定位、监测数据与建议文案 |

## 1.3 运行环境与部署说明

线上环境部署在**腾讯云轻量应用服务器**上，由 Nginx、PM2、Python 虚拟环境共同承载，与本地开发时的三进程结构一致（前端静态资源 + Node Mock API + Flask 分析服务）。

| 项目 | 配置 |
|------|------|
| 服务器名称 | 腾讯云轻量应用服务器 |
| CPU | 4 核 |
| 主频 | 2.50 GHz |
| 内存 | 16 GB |
| 硬盘 | 220 GB 云盘 |
| 运行内容 | 托管 Vue 前端构建产物；运行 Node.js（json-server，端口 3000）与 Python（Flask，端口 5000）双后端；Nginx 监听 88 端口对外提供访问并做反向代理 |

**端口与职责（生产）：**

- **88**：Nginx，对外访问入口；静态文件为 `pnpm build` 后的 dist；`/api` 转发至后端。
- **3000**：json-server，提供登录、监测点、预警、NDVI 摘要、土壤湿度趋势、灾害规则评估等 REST / Mock 接口；由 Node 项目或 PM2 守护进程。
- **5000**：Flask（`server/app.py`），处理 `/api/analysis/image` 图片分析请求；建议在独立 Python 虚拟环境（如 py-project-env）中运行。

面板管理使用宝塔；SPA 路由刷新 404 问题已通过 Nginx `try_files` 配置处理。线上故障排查可参考仓库内 `deploy/线上故障排查笔记.md`。

# 第五章 常见问题

## 5.1 登录与访问

**问：演示账号登不上去，先看哪里？**  
答：先确认访问的是 `http://82.157.234.123:88`，不是 https，也不要漏掉 88 端口。演示登录推荐使用手机号 `13800000000`、验证码 `2026`，角色选择「农技员」；旧密码 `123456` 仍作为备用密码兼容。若页面提示 401，通常表示请求已经到达后端，只是手机号、验证码、角色或备用密码没有匹配上；若 Network 面板里 `/api/login` 是 404 或 502，则优先排查 Nginx 反向代理和 3000 端口的 Mock 服务。

**问：忘记密码或想换测试账号怎么办？**  
答：当前演示库没有单独做“找回密码”流程。维护人员可在 `src/mock/db.json` 或线上 `api_mock/db.json` 的 `users` 表里调整用户记录；验证码逻辑由 Mock 服务处理，默认演示码为 `2026`。正式上线时再接入短信、邮箱或管理员重置流程。

**问：刷新页面后出现 404，是不是前端坏了？**  
答：不一定。这个项目是 Vue 单页应用，直接刷新 `/map`、`/warnings` 这类路由时，需要 Nginx 把找不到的路径交回 `index.html`。线上已按 `try_files $uri $uri/ /index.html;` 处理；如果后续换服务器或重新建站点，先检查这一段配置。

**问：整站突然打不开，演示前怎么快速判断？**  
答：按“外网入口、前端文件、两个后端”的顺序查。88 端口要在腾讯云和宝塔两处都放行；Node 项目 `api_mock` 负责登录、预警和地图数据；Python 项目 `api_flask` 负责图片分析。维护记录里曾遇到过 88 端口被关、`node_modules` 丢失、Nginx 反代被覆盖等情况，现象很像，但处理方法不同。

## 5.2 数据与地图

**问：地图打开了，但没有监测点？**  
答：先点页面上的「刷新数据」。如果仍然没有点，打开浏览器 Network 看 `/api/monitorPoints` 是否成功返回。地图点位来自 Mock 数据库，不是前端写死的图片；3000 端口服务停掉、反代规则丢失，或者 `db.json` 里 `monitorPoints` 被误删，都会让地图看起来“空了”。

**问：地图点位和预警数量对不上？**  
答：这是联动数据没有刷新时最容易出现的现象。预警列表、首页统计、地图弹窗都读同一批 `alerts` 和 `monitorPoints` 数据，但页面切换时可能保留了旧状态。可以先刷新当前页；维护人员再检查 `pointId` 是否能在监测点表中找到对应记录。一个监测点允许挂多条预警，所以“预警条数多于点位数”是正常的。

**问：相关数据 Tab 一直转圈？**  
答：正常只是短暂加载，用来模拟切换传感器、无人机、气象、GIS 数据源时的等待。如果长时间不结束，先看控制台是否有脚本报错；若同时地图、预警也加载失败，多半是 Mock 服务或 `/api` 代理问题，而不是图表组件本身。

**问：手机或窄屏上找不到菜单？**  
答：点击左上角的菜单按钮打开「功能导航」抽屉。地图、表格和图表在窄屏下会自动压缩，适合临时查看；正式演示建议使用 PC 或平板，避免地图弹窗和表格按钮挤在一起。

## 5.3 智能分析

**问：图片上传后提示失败，应该查前端还是后端？**  
答：两边都要看，但先看请求地址。图片分析走 Flask，路径是 `/api/analysis/image`，线上由 Nginx 转到 5000 端口，本地由 Vite 代理转到 Flask。若返回 404，多半是 `/api/analysis/` 的反代规则没生效；若返回 500，再去看 Python 控制台或宝塔 Python 项目日志。

**问：为什么有时上传成功，却没有生成预警？**  
答：完整流程是“Flask 返回识别结果与建议 → 前端组装预警 → json-server 写入 `alerts`”。如果只弹出识别结果、预警页没有新增记录，重点检查保存预警的请求是否发到了 3000 端口，以及 `store.createAlert` 是否真的调用了后端接口。开发时可以盯着 `db.json` 或 json-server 终端日志，看是否出现 `POST /alerts`。

**问：识别结果为什么不像真实模型？**  
答：当前版本为了保证比赛演示稳定，`server/app.py` 仍是 Mock 识别，没有接入外部大模型，也没有加载训练权重。但它不再是简单随机返回，而是按“预处理 → 特征提取 → 分类与建议”组织：图片摘要会影响斑点分数、纹理分数、置信度和建议文案。后续若接入 PyTorch、TensorFlow 等模型，主要替换 `run_ai_model_prediction` 的内部逻辑，前端上传表单和预警归档流程可以继续沿用。

**问：图片格式有什么限制？**  
答：建议使用 JPG、PNG 或 WEBP，文件不要过大，2MB 以内更稳。若图片为空、文件名异常、格式不在允许列表内，或浏览器没有正确构造 `FormData`，Flask 会返回 400 或前端显示分析失败。

## 5.4 预警与决策

**问：新建预警后，地图上为什么没有新增一个点？**  
答：预警不是新点位，它会挂到已有监测点上。新建时选择的监测点会对应 `pointId`，地图仍显示原来的 marker；打开该点弹窗，才能看到未处理预警提示。同一监测点可以连续产生多条预警，这一点在演示时容易被误解。

**问：点击“标记解决”后，其他页面会跟着变吗？**  
答：会，但需要页面重新取数或状态同步完成。预警页把 `handled` 改为 `true` 后，首页待处理数量、地图弹窗提示、智慧决策左侧列表都会受影响。如果某个页面还显示旧数字，先刷新或切换页面再看。

**问：智慧决策右侧为空？**  
答：右侧内容依赖左侧选中的“待处理”预警。若左侧没有数据，先到「灾害预警」新建一条，或在已有记录中点「标记未处理」。如果列表有内容但右侧不变，检查该预警的 `pointId` 是否能匹配到监测点，否则小地图和监测数据无法拼出来。

**问：系统给出的处置建议能直接用于生产吗？**  
答：不建议直接作为真实农事决策依据。当前建议是按预警级别、监测值和固定模板生成的演示内容，适合说明“发现问题后如何组织处置流程”。真实生产场景还需要接入当地农技规范、传感器阈值和人工复核。

## 5.5 使用注意

- 公共电脑演示后请退出登录，并清理浏览器里保留的登录状态。
- 线上地址目前使用 http 访问，若后续配置 SSL，需要同步检查 Nginx 反代和前端 API 路径。
- 3000 和 5000 端口不需要对公网开放，外部用户只访问 88 端口；排查时不要把“公网访问不到 3000/5000”误判为服务异常。
- 演示数据、Mock 识别结果和规则建议只用于展示系统流程，不能直接替代实地农情判断。
- 修改 `db.json` 前建议先备份。json-server 会把新增预警写回文件，手动改数据时要避免和正在运行的服务互相覆盖。
- 推荐使用 Chrome 或 Edge 最新版；手机端可临时查看，但地图弹窗、图表 Tooltip 和表格按钮在大屏上更适合展示。
