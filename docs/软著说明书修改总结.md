# 软著说明书修改总结

本文记录 `docs/软件使用说明书.md` 本次面向软件著作权申请和“挑战杯”项目材料用途所做的修改，重点说明修改原因、修改内容和调整原则。

---

## 一、涉及文件

- `docs/软件使用说明书.md`

---

## 二、修改原因

原说明书在前期修改中补充了较多真实部署、开发联调、演示排查和 Mock 服务细节，这些内容有助于项目维护，但不完全适合直接作为软件著作权登记和项目评审材料提交。

本次调整主要基于以下考虑：

1. **软著材料应突出软件功能和使用流程**  
   说明书需要体现软件名称、系统功能、界面结构、操作步骤和运行环境，而不是重点说明开发命令、端口排障、Mock 数据或具体后端实现细节。

2. **挑战杯材料应保持项目表达正式、清晰**  
   参赛材料更适合展示系统解决的农业问题、业务流程和用户价值，不宜出现过多“本地调试”“演示数据”“排障笔记”等维护人员口吻。

3. **降低模板化和开发化痕迹**  
   原文中部分章节存在通用软件说明书模板表达，也有部分过于开发化的技术说明。本次通过统一领域术语、突出作物灾害监测业务场景、保留真实功能模块，提升文档的项目辨识度。

4. **避免对外材料暴露不必要内部信息**  
   对外说明书不再展开 Mock 服务、具体端口、源码文件、部署脚本、接口路径等内部实现内容，仅保留用户理解和使用系统所需的信息。

---

## 三、主要修改内容

### 3.1 调整文档定位

- 将说明书定位从“开发/演示/排障混合材料”调整为“正式软件使用说明书”。
- 保留软件名称、版本号、终端类型、开发单位、适用对象等基础信息。
- 将适用对象调整为农业合作社管理人员、农技推广人员、项目评审、教学培训及系统维护人员。

### 3.2 重写系统简介口径

- 将“作物灾害监测、预警与辅助决策”作为系统主线。
- 保留系统核心能力：
  - 地图查看监测点位置与状态；
  - 查看传感器、无人机、气象、GIS 等农情数据；
  - 上传作物图片进行智能分析；
  - 新建、处理和删除预警记录；
  - 针对待处理预警查看监测点信息和处置建议。
- 删除或弱化不适合软著材料的开发实现描述。

### 3.3 新增统一领域术语

新增“统一领域术语”章节，统一以下表达：

| 术语 | 说明 |
|------|------|
| 监测点 | 地图上的农田或果园监测位置 |
| 农情数据 | 传感器、无人机遥感、气象、GIS 等业务数据 |
| 预警记录 | 系统或用户创建的风险提示记录 |
| 待处理预警 | 尚未完成处置的预警记录 |
| 已处理预警 | 已完成处置或确认闭环的预警记录 |
| 智能分析 | 上传作物图片后生成识别结果和建议的过程 |
| 处置建议 | 系统生成的辅助处理建议 |

该调整减少了“点位、设备、告警、事件、AI 方案”等混用情况，使说明书语言更稳定。

### 3.4 规范运行环境说明

- 将原来偏部署细节的说明，调整为浏览器/服务器架构说明。
- 保留用户侧需要了解的运行条件：
  - 浏览器访问；
  - 前端页面服务；
  - 业务接口服务；
  - 图片分析服务。
- 删除 Mock、json-server、Flask 文件路径、3000/5000 端口、Nginx 排障等内部维护信息。

### 3.5 规范登录与退出说明

- 保留登录页面、手机号、验证码、角色选择、备用登录方式和退出登录流程。
- 删除后端端口、接口失败排查等开发化内容。
- 将角色说明调整为面向用户理解的管理员、农技员、合作社三类角色。

### 3.6 调整第四章功能操作说明

第四章从“按演示场景讲解”调整为“按系统功能模块说明”，更符合软著说明书格式。

当前结构包括：

1. 登录与身份选择；
2. 首页概览；
3. 相关数据；
4. 灾害实时监测；
5. 智能分析；
6. 灾害预警；
7. 智慧决策；
8. 移动端与用户菜单。

每个模块保留进入方式、页面内容、操作步骤和截图占位，便于后续导出 Word 或 PDF 作为申报材料。

### 3.7 重写第五章使用注意事项

将原有偏 FAQ 和排障笔记的内容改为正式使用注意事项，包含：

- 账号与登录；
- 数据查看；
- 图片分析；
- 预警处置；
- 运行环境。

调整后内容更适合普通用户、评审人员和材料审查人员阅读。

### 3.8 精简附录

- 将附录改为“软件信息、运行环境建议、技术支持”三部分。
- 删除本地开发启动命令、内部文档链接、部署恢复文档、源码导出说明等不适合软著使用说明书正文的内容。
- 保留软件全称、版本、终端类型、适用方向、开发单位等申报材料常用信息。

## 四、删除或弱化的内容

本次说明书中特别删除或弱化了以下内容：

- Mock 数据、Mock 服务、随机识别等演示实现描述；
- json-server、Flask 文件路径、Nginx、PM2、3000/5000 端口等部署细节；
- 本地开发命令和源码维护说明；
- 浏览器 Network 排障、服务反代排查等维护人员口吻；
- “演示前自检”“排障顺序”等不适合软著说明书的章节；
- 过多接口字段、源码字段、内部文件路径和开发依赖描述。

---

## 五、保留的内容

为保证说明书仍能支撑软著申请和挑战杯项目材料，本次保留了以下内容：

- 软件名称、版本、终端类型、开发单位；
- 系统功能模块一览；
- 登录、退出、主界面、导航、搜索、地图说明；
- 农情数据展示、地图监测、智能分析、预警管理、智慧决策等核心功能操作；
- 移动端适配说明；
- 运行环境建议和技术支持说明；
- 截图占位符，便于后续补充实际界面图。

---

## 六、修改后的文档特点

修改后的 `docs/软件使用说明书.md` 具有以下特点：

1. **更适合软著提交**  
   文档重点说明软件功能、界面和使用步骤，避免过度展示开发实现。

2. **更适合挑战杯评审阅读**  
   文档围绕作物灾害监测、农情数据、预警处置和智慧决策展开，项目主题更明确。

3. **术语更加统一**  
   全文统一使用“监测点、农情数据、预警记录、待处理预警、处置建议”等农业业务术语。

4. **开发细节更少**  
   对外材料中不再出现不必要的本地调试、Mock、部署排障和源码文件信息。

5. **可继续补图导出**  
   现有截图占位符仍保留，可在正式提交前替换为系统实际截图。
