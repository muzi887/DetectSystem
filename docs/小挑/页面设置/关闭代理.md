这个错误代码 `net::ERR_CERT_AUTHORITY_INVALID` 的意思是：**浏览器不信任该网站提供的 SSL/HTTPS 安全证书**。

简单来说，你的浏览器向 `www.mocky.io` 发起请求，服务器出示了它的“身份证”（证书），但你的浏览器（或者操作系统）认为这个“发证机构”（Authority）是伪造的或不可信的，因此为了安全拦截了请求。

针对你访问的是 `mocky.io`（一个常用的接口模拟工具），出现这个错误通常有以下几种原因，按**可能性从高到低**排列：

### 1. 你正在使用抓包工具（最常见的开发者场景）

如果你是开发或测试人员，电脑上可能开启了 **Fiddler, Charles, Whistle, Burp Suite** 或者 **Postman** 的抓包代理功能。

- **原因：** 这些工具为了解密 HTTPS 流量，会生成一个“伪造”的中间人证书。如果你的电脑没有将这些工具的 **Root Certificate（根证书）** 安装到系统的“受信任的根证书颁发机构”列表中，浏览器就会报这个错。
- **解决方法：**
    - 关闭抓包工具。
    - 或者，在抓包工具的设置里找到 `Install Root Certificate`（安装根证书）并信任它。

### 2. 杀毒软件的“HTTPS 扫描”功能

某些杀毒软件（如 Kaspersky, Bitdefender, Avast 等）会拦截并扫描加密的网络流量。

- **原因：** 杀毒软件在中间充当了代理，替换了原来的证书，但浏览器不认杀毒软件的证书。
- **解决方法：** 暂时暂停杀毒软件，或者在杀毒软件设置中关闭“Web防护”或“HTTPS 扫描/加密连接扫描”。

### 3. 系统时间不正确

- **原因：** SSL 证书都有有效期。如果你的电脑系统时间回到了过去（比如 2010 年）或者去了未来，浏览器会认为证书“尚未生效”或“已过期”，从而判定证书无效。
- **解决方法：** 校准你的电脑系统时间。

### 4. 操作系统或浏览器版本过旧

- **原因：** `mocky.io` 可能使用的是较新的证书颁发机构（例如 Let's Encrypt）。如果你使用的是 **Windows 7** 且没有打补丁，或者很老版本的 Chrome，系统里缺乏最新的根证书库，就会不认得新的证书。
- **解决方法：** 更新操作系统或浏览器，或者手动下载并安装 `ISRG Root X1` 证书。

### 5. 公司网络/代理/VPN 问题

- **原因：** 如果你在公司内网，公司的网关可能会进行 SSL 解密审计；或者你使用的 VPN 节点证书有问题。
- **解决方法：** 尝试断开 VPN，或切换到手机热点测试一下是否正常。

---

### 快速排查建议：

1. **先看时间：** 电脑右下角时间对不对？
2. **检查代理：** 关闭 Fiddler/Charles 等软件，或者在 Chrome 设置 -> 系统 -> 打开计算机的代理设置，确保“使用代理服务器”是**关闭**的。
3. **尝试无痕模式：** 打开 Chrome 的无痕（隐私）模式访问该链接。如果无痕模式能打开，说明是某个浏览器插件导致的。
