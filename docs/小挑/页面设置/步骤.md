# 核心思路（一个人做项目的高效法）

- 先做 MVP（可演示的最小版本）：登录 → 仪表盘（静态卡片）→ 监测点地图 → 预警列表。把可见流程跑通。
    
- 每个功能采用「先可用、再优化」：先用 Mock 数据快速实现，再把实现拆成小练习掌握原理。
    
- 每天做**小批量迭代**（小功能完结+至少一次 commit）。每个小功能都写明“我要学会的点”并验收。
    
- 保持代码可读、组件化；先实现“功能”，后重构为可复用组件（这个过程就是学习最佳时机）。

# 立刻开始的“最小可运行计划”

下面是你**马上可以启动并完成第一个演示（有界面、可登录到 Dashboard 并拿到 mock 数据）** 的最小步骤。我会把每一步拆成“做什么 + 为什么学到什么 + 强化练习”。

### 步骤 0 — 画个草图（强烈建议）

- 做法：在纸上或 Figma 画出 3 个页面：Login、Dashboard、Monitor（地图+点）。
    
- 学到的：界面布局思路、交互流程（路由跳转、token 保存、数据请求）。
    

### 步骤 1 — 用 Vite 快速建前端骨架

- 做什么：用 Vite 创建项目；安装依赖：Vue3、Vue Router、Pinia、Ant Design Vue、Axios、Leaflet、ECharts（后两个可后面装）。
    
- 学到的：项目结构，如何把依赖引入并启动项目。
    
- 强化练习：启动后修改 `App.vue` 标题为你的项目名并保存，观察热更新（理解 dev server 工作）。
    

> （如果你需要，我可以把创建命令和 `package.json` 的最小内容一次性发给你——你可以先看懂再运行。）

### 步骤 2 — 搭路由与基本页面（必须做）

- 做什么：建立 `/login`、`/dashboard`、`/monitor` 三个路由；登录页按钮跳转到 `/dashboard`（初期不验真）。
    
- 学到的：router 的基础、导航守卫思想。
    
- 强化练习：把 `/dashboard` 改成只能在「已登录」时访问（用 Pinia 存一个 `isLogged`），然后尝试手动清缓存，观察行为；在登录页打印 `router.push` 返回值。
    

### 步骤 3 — Pinia：用户状态与简单登录流程

- 做什么：写 `useUserStore`，包含 `login()`（调用 mock API）、`logout()`、`userInfo`、`token`。登录后保存 token 到 `localStorage`。
    
- 学到的：状态持久化、actions 的副作用、组件如何使用 store。
    
- 强化练习：把 `token` 存到 `sessionStorage` 改成 `localStorage`，观察刷新后是否保持登录；在 store 内加一个 computed（getter）比如 `isAdmin`。
    

### 步骤 4 — Mock 数据与 Axios（让前端「看见」数据）

- 做什么：用 `json-server` 或一个本地 `mock/db.json`，实现 `/monitor/points` 与 `/alerts` 两个接口。把 Axios baseURL 指向 mock 服务，Dashboard 请求 `/monitor/points` 并显示数量。
    
- 学到的：HTTP 请求流程、mock 的作用、如何根据返回渲染组件。
    
- 强化练习：把一个监测点的 `status` 从 `normal` 改为 `warning`，并让前端颜色随之变化（通过条件 class）。
    

### 步骤 5 — 地图（Leaflet）显示监测点

- 做什么：在 Monitor 页面用 Leaflet 显示地图并把 mock 点渲染成 Marker，点击弹出当前数据（temp、soilMoisture）。
    
- 学到的：第三方库集成、Prop传递、异步加载数据到地图。
    
- 强化练习：给每个 Marker 加一个“模拟触发警报”按钮，点击后向 `/alerts` POST 一个新警报（mock server 可以接收），然后前端刷新 Alerts 列表。
    

### 步骤 6 — Alerts 页面（表格 + 处理）

- 做什么：显示 alert 列表、按等级过滤、点“标记为已处理”调用 API。
    
- 学到的：表格渲染、分页（简单实现）、组件通信（map -> alerts）。
    
- 强化练习：实现“只显示最近 24 小时”的筛选（自己计算时间戳并过滤）。
    

### 步骤 7 — 简单可视化（Dashboard）

- 做什么：用 ECharts 或 AntD 的图表做一张“过去 7 天预警数量变化”折线图（用 mock）。
    
- 学到的：数据到图表的映射、接口设计思路、图表交互。
    
- 强化练习：加个时间范围选择器（开始/结束），并把图表随之更新。
    

### 步骤 8 — 重构 & 提交（学习收尾）

- 做什么：把重复的 UI 抽成组件（Card、StatusTag、MapCard），写 README 记录如何启动。每做完一个功能做一次 commit（小步快频）。
    
- 学到的：组件复用、干净的仓库管理、如何写能被别人读懂的 README（演示必备）。

# 如何避免“照搬代码却没学会”的恶性循环（实践策略）

1. **每次复制示例前做 3 件事**：
    
    - 读懂这段代码的每一行（能用自己的话解释）
        
    - 改动一个地方（变量名、注释、console.log）并观察结果
        
    - 写一个小测试/调试步骤证明你理解了（例如用 mock 改数据、看页面变化）
        
2. **用“改造任务”强迫理解**：拿一个现成组件，做两处改造：样式改、行为改（比如把点击变为双击）。如果能改动并无 bug，就是学会了。
    
3. **写“实现要点文档”**：每完成一个页面，写 3-5 行说明：它做了什么、核心 state、主要 API、已知问题。下次回看就能快速回忆。
    
4. **做小但完整的功能闭环**：不要半途停留在“页面长得像”而没有交互。真正可演示的功能是最能带来学习的（例如：登录后能看到 map，并可以触发预警）。
    
5. **保持版本控制**：每个小特性一个分支、每次提交写明“我学到的点”。回顾 commit 历史比读教程更能巩固理解。

# 调试/查错常见技巧（新手必备）

- 在 Axios 请求处加 `console.log(response)`，先看后端（mock）返回是否正确。
    
- 在组件里用 `watch` 监听关键 props/state，`console.log` 看数据流动。
    
- Vue Devtools + Pinia 插件：实时查看 state。
    
- 浏览器 Network 面板：检查请求 URL、请求头（token）、返回码。
    
- 如果地图不显示坐标，先 `console.log(lat,lng)`，再确认 Leaflet 的 tile URL 是否可达。

### 练习版：`src/router/index.ts`

```ts
import { createRouter, createWebHistory } from 'vue-router'
import Login from '@/pages/Login.vue'
import Dashboard from '@/pages/Dashboard.vue'
import Monitor from '@/pages/Monitor.vue'
import { useUserStore } from '@/stores/user'

const routes = [
  { path: '/login', component: Login },
  { path: '/', component: Dashboard, meta: { requiresAuth: true } },
  { path: '/monitor', component: Monitor, meta: { requiresAuth: true } }
]

const router = createRouter({ history: createWebHistory(), routes })

router.beforeEach((to, from, next) => {
  const store = useUserStore()
  if (to.meta.requiresAuth && !store.token) return next('/login')
  next()
})

export default router
```

**练习任务**：在 `beforeEach` 添加 `console.log('navigation to', to.path)`，观察导航守卫何时运行；然后尝试不登录直接访问 `/`，验证会跳到 `/login`。
