### 1. 修改 `src/stores/user.ts` (简化版)

这个修改是**强烈建议**的。主要目的是在用户登录后，将用户信息也保存到 `localStorage` 中。这样即使用户刷新了页面，您的应用顶部导航栏等位置依然能显示用户名，提升了用户体验，也避免了刷新后数据丢失的问题。

```typescript
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import axios from 'axios'

// 建议定义一个接口，让代码更清晰
interface UserInfo {
    id?: number;
    name?: string;
    phone?: string;
    role?: 'admin' | 'user'; // role 字段可以保留，只是暂时不用它来做判断
}

// 创建Store实例
export const useUserStore = defineStore('user', () => {
    // 从 localStorage 初始化 token 和 userInfo
    const token = ref<string>(localStorage.getItem('token') || '')
    const userInfo = ref<UserInfo>(JSON.parse(localStorage.getItem('userInfo') || '{}'))

    const isLogged = computed(() => !!token.value)

    // 登录 API
    async function loginApi(phone: string, password: string) {
        const res = await axios.post('/api/login', { phone, password })
        
        if (res.data && res.data.token) {
            token.value = res.data.token
            userInfo.value = res.data.user

            // 核心修改：将 token 和 userInfo 都持久化
            localStorage.setItem('token', token.value)
            localStorage.setItem('userInfo', JSON.stringify(userInfo.value)) // 必须将对象字符串化
        }

        return res.data
    }

    function logout() {
        token.value = ''
        userInfo.value = {}
        // 退出时也一并清除
        localStorage.removeItem('token')
        localStorage.removeItem('userInfo')
    }

    // 注意这里我们不需要导出 role 相关的计算属性了
    return { token, userInfo, isLogged, loginApi, logout }
})

```

**这个修改做了什么？**

1. **持久化用户信息**：登录成功后，将 `userInfo` 对象存入 `localStorage`。
2. **恢复用户信息**：应用启动时，从 `localStorage` 读取 `userInfo`。
3. **清空用户信息**：退出登录时，从 `localStorage` 移除 `userInfo`。

这保证了只要用户在登录状态，`userInfo` 就始终可用，解决了页面刷新的问题。

### 2. 修改 `src/router/index.ts` (简化版)

这里的修改是**必须的**。我们将恢复到您最初的路由守卫逻辑，即只检查 `token` 是否存在，完全移除角色判断的部分。

```typescript
import type { RouteRecordRaw } from 'vue-router'
import { createRouter, createWebHistory } from 'vue-router'
// 注意：现在不需要在路由文件中引入 userStore 了

// --- 组件导入部分保持不变 ---
const Login = () => import('../views/Login.vue')
const Dashboard = () => import('../views/Dashboard.vue')
const Monitor = () => import('../views/Monitor.vue')
const Alerts = () => import('../views/Alerts.vue')
const RelatedData = () => import('../views/RelatedData.vue')
const UserProfile = () => import('../views/user/UserProfile.vue') 
const MapVisualization = () => import('../views/user/MapVisualization.vue') 
const DataAnalysis = () => import('../views/user/DataAnalysis.vue') 
const WarningSystem = () => import('../views/user/WarningSystem.vue') 
const DecisionSupport = () => import('../views/user/DecisionSupport.vue') 

// --- 路由配置 routes: RouteRecordRaw[] 保持不变 ---
// 您之前接受的路由结构（包含 /admin 子路由）是完美的，完全符合您的要求，无需改动。
// 我只在这里移除了 admin 路由上的 meta.role 属性，避免混淆。
const routes: RouteRecordRaw[] = [
    { path: '/', component: MapVisualization, name: 'Home' },
    { path: '/login', component: Login, name: 'Login' },
    { path: '/related-data', component: RelatedData, name: 'RelatedData', meta: { requireAuth: true } },
    { path: '/profile', component: UserProfile, name: 'UserProfile', meta: { requireAuth: true, title: '个人中心' } },
    { path: '/map', component: MapVisualization, name: 'MapVisualization', meta: { requireAuth: true, title: '实时监测' } },
    { path: '/analysis', component: DataAnalysis, name: 'DataAnalysis', meta: { requireAuth: true, title: '数据分析' } },
    { path: '/warnings', component: WarningSystem, name: 'WarningSystem', meta: { requireAuth: true, title: '预警中心' } },
    { path: '/decision', component: DecisionSupport, name: 'DecisionSupport', meta: { requireAuth: true, title: '决策支持' } },
    {
        path: '/admin',
        redirect: '/admin/dashboard',
        // 【核心修改】移除了 meta: { role: 'admin' }，因为我们不再检查角色
        meta: { requireAuth: true }, 
        children: [
            { path: 'dashboard', component: Dashboard, name: 'Dashboard', meta: { title: '管理员仪表盘' } },
            { path: 'monitor', component: Monitor, name: 'AdminMonitor', meta: { title: '后台监测管理' } },
            { path: 'alerts', component: Alerts, name: 'AdminAlerts', meta: { title: '后台警报管理' } }
        ]
    },
    { path: '/:pathMatch(.*)*', name: 'NotFound', component: () => import('../views/NotFound.vue') }
]

// 创建路由实例
const router = createRouter({
    history: createWebHistory(),
    routes
})

//【核心修改】全局前置守卫恢复到最简单的版本
router.beforeEach((to) => {
    // 这个守卫逻辑直接从 localStorage 读取 token，简单有效
    const token = localStorage.getItem('token')

    // 认证检查：如果路由需要认证（meta.requireAuth为true）但用户未登录（没有token），
    // 就强制跳转到登录页面。
    if (to.meta.requireAuth && !token) {
        return { path: '/login', query: { redirect: to.fullPath } }
    }
    
    // 如果已登录，或页面不需要认证，则直接放行。
    // 无需任何角色判断。
})

// 导出路由配置
export default router
```

**这个修改做了什么？**

1. **简化路由守卫**：`beforeEach` 函数恢复到只检查 `localStorage` 中是否存在 `token`。这是实现“登录后可访问”的最直接方式。
2. **移除 `meta.role`**：从 `/admin` 路由配置中删除了 `role: 'admin'`，因为守卫逻辑已经不再使用它，这样能让代码更清晰。

总结一下，采用以上两份简化版的代码，就能完美实现您的当前需求：**跑通普通用户登录，并保留所有旧页面（现在任何登录用户都可访问），同时避免了复杂的角色权限判断。**
