
1. **`src/stores/user.ts`**：我们需要让 Pinia Store 能够存储和管理用户的 `role` 信息，并在页面刷新后依然能够保持状态。
2. **`src/router/index.ts`**：我们需要在全局前置守卫 `beforeEach` 中，从 Store 获取用户角色，并与路由元信息 `meta.role`进行比对。

下面是详细的修改步骤和代码。

### 步骤 1: 修改 Pinia Store (`src/stores/user.ts`)

首先，我们需要让 `user` store 保存完整的用户信息，特别是 `role` 字段，并将其持久化到 `localStorage` 中，以便在刷新页面后路由守卫能正确获取角色信息。

**修改后的 `// src/stores/user.ts` 如下：**

```typescript
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import axios from 'axios'
// import http from '@/utils/http' // 如果有封装的 http，建议使用

// 定义用户信息的接口，增加 role 字段
interface UserInfo {
    id?: number
    name?: string
    phone?: string
    role?: 'admin' | 'user' // 明确角色类型
}

// 创建Store实例
export const useUserStore = defineStore('user', () => {
    // 1. 从 localStorage 初始化 token 和 userInfo
    const token = ref<string>(localStorage.getItem('token') || '')
    // 用户信息也需要从 localStorage 加载，防止刷新丢失角色信息
    const userInfo = ref<UserInfo>(JSON.parse(localStorage.getItem('userInfo') || '{}'))

    // 2. 计算属性
    const isLogged = computed(() => !!token.value)
    const userRole = computed(() => userInfo.value.role) // 新增一个计算属性，方便获取角色

    // 备用：真实请求
    async function loginApi(phone: string, password: string) {
        // 注意：这里的 /api/login 路径需要与您的 vite.config.ts 或 vue.config.js 中的代理设置匹配
        const res = await axios.post('/api/login', { phone, password })
        
        if (res.data && res.data.token) {
            token.value = res.data.token // 使用服务器返回的 token
            userInfo.value = res.data.user // 保存完整的用户信息，包含 role

            // 3. 将 token 和 userInfo 持久化到 localStorage
            localStorage.setItem('token', token.value)
            localStorage.setItem('userInfo', JSON.stringify(userInfo.value)) // 必须将对象字符串化
        }

        return res.data
    }

    function logout() {
        token.value = ''
        userInfo.value = {}

        // 4. 退出登录时，清除 localStorage 中的所有相关信息
        localStorage.removeItem('token')
        localStorage.removeItem('userInfo')
    }

    // 5. 返回所有 state 和 actions，新增了 userRole
    return { token, userInfo, isLogged, userRole, loginApi, logout }
})

```

**主要变更点解释：**

1. **定义 `UserInfo` 接口**：明确了 `userInfo` 对象的结构，特别是 `role` 字段。
2. **从 `localStorage` 初始化 `userInfo`**：确保当用户刷新页面时，`userInfo` (包含角色)能够被恢复。
3. **持久化 `userInfo`**：在 `loginApi` 成功后，将完整的用户信息对象（通过 `JSON.stringify`）存入 `localStorage`。
4. **清除 `userInfo`**：在 `logout` 时，一并清除 `localStorage` 中的用户信息。
5. **新增 `userRole` 计算属性**：提供一个简洁的方式在应用的其他地方（比如路由守卫）获取当前用户的角色。

### 步骤 2: 修改路由守卫 (`src/router/index.ts`)

现在 Store 已经准备好了，我们可以在路由守卫中解锁 `TODO` 部分的逻辑了。

**修改后的 `// src/router/index.ts` 如下：**

```typescript
import type { RouteRecordRaw } from 'vue-router'
import { createRouter, createWebHistory } from 'vue-router'
// 1. 引入 useUserStore 以便在守卫中使用
import { useUserStore } from '@/stores/user'

// ... (您的路由组件导入代码保持不变) ...
const Login = () => import('../views/Login.vue')
const Dashboard = () => import('../views/Dashboard.vue')
// ... 其他组件 ...

const routes: RouteRecordRaw[] = [
    // ... (您的路由配置保持不变) ...
    // 其中 /admin 路由已经配置了 meta: { requireAuth: true, role: 'admin' }
    {
        path: '/admin',
        redirect: '/admin/dashboard',
        meta: { requireAuth: true, role: 'admin' }, // 这个 meta 是关键
        children: [
            //...
        ]
    },
]

// 创建路由实例
const router = createRouter({
    history: createWebHistory(),
    routes
})

//全局前置守卫
router.beforeEach((to) => {
    // 2. 在守卫函数内部获取 user store 实例
    const userStore = useUserStore()
    const token = userStore.token // 建议从 store 获取 token，保持单一数据源
    const userRole = userStore.userRole // 从 store 获取角色

    // 认证检查：如果路由需要认证但用户未登录，跳转到登录页面
    if (to.meta.requireAuth && !token) {
        return { path: '/login', query: { redirect: to.fullPath } }
    }

    // 3. 权限检查：如果路由需要特定角色，但用户角色不匹配
    const requiredRole = to.meta.role as string | undefined

    if (requiredRole && userRole !== requiredRole) {
        // 如果用户角色不符合要求 (例如，普通用户尝试访问 admin 页面)
        // 则重定向到他们有权限的首页（这里假设是 /map）
        // 使用 replace: true, 用户无法通过浏览器后退按钮返回到被拒绝的页面
        return { path: '/map', replace: true } 
    }

    // 如果所有检查都通过，则允许导航
    // return true; // 在 Vue Router 4.x 中，如果没有返回值，则默认放行
})

// 导出路由配置
export default router
```

**主要变更点解释：**

1. **引入 `useUserStore`**：这样我们才能在守卫函数中访问用户状态。
2. **在 `beforeEach` 中获取 Store 实例**：注意，`useUserStore()` 必须在 `beforeEach` 函数内部调用，因为 Pinia 实例是在 Vue app 创建后才可用的。
3. **实现权限检查逻辑**：
    - 我们从 `to.meta.role` 获取目标路由所要求的角色。
    - `if (requiredRole && userRole !== requiredRole)` 这行代码是核心：
        - `requiredRole`：检查路由是否定义了权限要求。
        - `userRole !== requiredRole`：检查当前用户的角色是否与要求的角色不匹配。
    - 如果不匹配，就将用户重定向到普通用户的默认页面 `/map`，并使用 `replace: true` 提升用户体验。

现在，您的系统已经具备了完善的、基于角色的路由权限控制。普通用户将无法访问 `/admin` 下的任何页面。
