### 3.2 P1-1～P1-3：无人机历史对比

**UI 行为（`NdviLayerControls.vue`）：**

```text
[地块 ▼]  [影像日期 ▼]  [对比历史 ☐]  [对比日期 ▼]  [历史透明度 ━━━●━━ 50%]
                              ↑ 关闭时隐藏后两项
```

| 规则 | 说明 |
|------|------|
| 对比开关 | `compareEnabled`；关闭时清空 `compareNdviDate` 并移除第二层 |
| 对比日期选项 | 当前地块所有日期 **排除** 已选「影像日期」 |
| 无可对比期 | 该地块仅 1 期时，开关 disabled + tooltip「当前地块仅一期影像」 |
| 换地块 | `selectField` 内重置 `compareEnabled = false` |
| 透明度 | `compareOpacity` 默认 0.5，范围 0.2–0.8；只作用于**历史层** |

**Store 增量（`remoteSensing.ts`）：**

```typescript
const compareEnabled = ref(false)
const compareNdviDate = ref('')
const compareOpacity = ref(0.5)

const compareNdviLayer = computed(() =>
  compareEnabled.value && compareNdviDate.value
    ? layersForField.value.find((l) => l.date === compareNdviDate.value) ?? null
    : null
)

const compareNdviRaster = computed(() =>
  compareNdviLayer.value ? toRasterView(compareNdviLayer.value) : null
)
```

**地图层叠顺序（`RemoteSensingMap.vue`）：**

```text
底图 (gaodeSatellite)
  → compareOverlay（历史，opacity = compareOpacity）
  → rasterOverlay（当前，opacity = 1）
  → monitorLayer（仅 GIS）
```

当前期 `fitBounds` 逻辑与 P0 一致；对比层共用同一 `bounds`（同地块各期 bounds 相同）。

### 3.3 P1-4～P1-6：GIS 点击查墒情 + 监测点联动

**接口契约：**

```http
GET /api/moisture/value?lat=38.44&lng=116.10
```

```json
{
  "moisture": 30,
  "source": "nearest-point",
  "nearestPointId": 1,
  "pointName": "监测站 · 河间市",
  "distanceKm": 2.3
}
```

**Mock 实现（方案 A — 最近监测点）：**

- 读取 `db.monitorPoints`，按欧氏距离（或 Haversine）找最近点。  
- `moisture` 取该点 `soilMoisture`；`source` 固定 `nearest-point`。  
- 逻辑放入 `agriMockCore.cjs` 的 `queryMoistureByNearestPoint`，本地与部署 server 共用，避免双份算法漂移。

**前端事件流：**

```text
用户点击 GIS 地图
  → queryMoistureValue(lat, lng)
  → L.popup 显示墒情结果（独立于监测点 Popup）
  → 若 nearestPointId 存在 → monitorLayer.highlightPoint(id)
  → RelatedData 更新 lastMoistureQuery → AI 文案 / caption
```

**`useMonitorPointLayer` 增量：**

```typescript
function highlightPoint(pointId: number, zoom = 14) {
  const marker = markersById.get(pointId)
  if (!marker || !map) return
  map.flyTo(marker.getLatLng(), zoom, { duration: 0.8 })
  marker.openPopup()
}

return { render, updatePopups, detach, highlightPoint, cluster }
```

**GIS 模式注意：**

- 查值 Popup 与监测点 Popup **可并存**；查值 Popup 用 `L.popup()` 临时实例，不替换 marker 绑定。  
- Raster overlay 保持 `interactive: false`（P0），点击落在底图/空白处仍触发查值。  
- 建议在 caption 增加一行：`点击地图可查询该位置墒情（演示：最近监测点）`。

### 3.4 P1-7：AI 与界面文案

| 场景 | AI 文案策略 |
|------|-------------|
| GIS 无点击 | 保持 P0 默认墒情分布描述 |
| GIS 点击后 | `{{ pointName }} 附近墒情约 {{ moisture }}%（{{ source }}），{{ 与传感器一致/偏低/偏高 }}` |
| 联动高亮后 | 可追加「已定位至 {{ pointName }} 传感器」 |
| 无人机 Tab | 对比开启时副标题追加「对比 {{ compareNdviDate }}」；AI 可提「两期间 NDVI 变化」 |

左下 `map-caption`（GIS）可选展示：`最近查值：XX% · 监测站 · XXX`（`pointer-events: none` 不变）。

## 10. 风险与应对

| 风险 | 应对 |
|------|------|
| 两期 NDVI 同一张图，对比不明显 | 采用 §6.1 第二套 `imageAsset`；或答辩时说明「机制演示，生产为真实时序产品」 |

| 点击过于灵敏，拖动地图误触发 | `click` 与 `drag` 区分：仅 `mouseup` 且位移 < 5px 时查值 |
| 部署 Mock 无 `/moisture/value` | 必须同步改 `deploy/api_mock/server.js` + `agriMockCore.cjs`，不仅 sync JSON |
| 对比层 z-index 盖住当前层 | 历史层先 add，当前层后 add；当前 opacity 恒为 1 |
| 雄县/栾城无对比期被误认为 bug | UI disabled + tooltip；答辩按 P0 数据口径说明 |
