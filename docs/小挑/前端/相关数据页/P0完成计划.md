### 2.2 地块与监测站（Mock 最终口径）

原先方案文档中的 **A3 / B2** 仅为演示编号，已与 **3 个监测站** 对齐：

| 地块下拉 | `fieldId` | 关联监测站 `monitorPointId` | NDVI 影像日期 |
|----------|-----------|----------------------------|---------------|
| 1号地块（河间市） | `hejian` | 1 · 监测站 · 河间市 | **2 期**：2026-05-20、2026-05-01 |
| 2号地块（雄县） | `xiongxian` | 2 · 监测站 · 雄县 | **1 期**：2026-05-20 |
| 3号地块（栾城区） | `luancheng` | 3 · 监测站 · 栾城区 | **1 期**：2026-05-20 |

**说明**：影像日期下拉**按当前地块过滤**；换到雄县/栾城时只有 1 个日期是数据设计如此，不是删了河间的第二期。

### 2.3 无人机 vs GIS：两套图层逻辑

| Tab | 图层 | Mock 表 | 范围 |
|-----|------|---------|------|
| **无人机遥感** | NDVI 热力图 | `ndviLayers`（按 `fieldId`） | 选哪块地，`fitBounds` 飞到哪块地 |
| **GIS 数据** | 墒情热力图 | `moistureLayers`（**仅 1 条**） | 栅格贴在**栾城附近**；河间/雄县只有**监测点圆点**+ 传感器 Popup |
| **灾害实时监测** | 无热力图 | `monitorPoints` | 仅监测点，带「手动触发 / 标记解决」 |

答辩可表述：无人机是**分地块**的作物长势；GIS 演示为**一片区域墒情栅格 + 全省监测点校准**，非每县各一张墒情图（P1 可扩展）。

### 2.4 P0-5：Popup 如何做到 GIS 无按钮

**不是**两个页面共用一个 Popup 的 `.vue` 组件，而是共用 TypeScript：

```text
RelatedData (GIS) → RemoteSensingMap → createMonitorPointLayer(map, { readonly: true })
                                              ↓
                                    buildMonitorPopupHtml(..., { readonly: true })  // 不输出按钮 HTML

MapVisualization → createMonitorPointLayer(map, { onTriggerAlert, onResolveAlert })
                                              ↓
                                    buildMonitorPopupHtml(...)  // 含按钮 + popupopen 绑事件
```

### 2.5 P0-6：UI 保留与增强

| 项 | 处理 |
|----|------|
| 传感器折线图、气象三卡片、生成简报 | **未改逻辑** |
| 左下标题、来源、色标 | 保留；`z-index: 4` |
| 无人机左下 | `影像日期：{{ selectedNdviDate }}` |

### 2.6 P0-7：本地 Mock 与部署 Mock 的关系

```text
本地开发（必须两个终端）
  npm run dev   → 前端 5173，/api 代理到 3000
  npm run mock  → 读取 src/mock/db.json（每次 GET 会重载文件）

部署上线（改遥感数据后）
  1. 编辑 src/mock/db.json
  2. pnpm sync:mock-db   → 把 fields / ndviLayers / moistureLayers 写入 deploy/api_mock/db.json
  3. 上传 deploy/api_mock/ 并在服务器重启 Node Mock
```

| 操作 | 是否还要 `npm run mock` | 是否还要 `sync:mock-db` |
|------|-------------------------|-------------------------|
| 本地调页面、看地图 | **要**，与 `dev` 同时开 | **不要**（本地不读 deploy 目录） |
| 宝塔更新 Mock 数据 | 本地调试仍要 mock | **要**，再上传 deploy |

`sync:mock-db` **不能代替** `npm run mock`：前者只复制 JSON，后者才是接口服务。

### 2.7 接口一览（json-server 自动路由）

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/api/fields` | 地块列表 |
| GET | `/api/ndviLayers` | NDVI 图层（前端按 `fieldId` 过滤） |
| GET | `/api/moistureLayers` | 墒情图层 |
| GET | `/api/monitorPoints` | 监测点（GIS 叠加；原有监测页） |

Mock 失败时：`RelatedData` 提示「遥感图层加载失败，已使用本地演示数据」，地图仍用 `remoteSensingLayers.ts` 兜底图。

## 9. 风险与应对

| 风险 | 应对 |
|------|------|
| 贴图与 bounds 不准 | 调整 `db.json` 中 `bounds`；本地保存后刷新即可 |
| 遥感接口失败 | 检查 mock 是否启动；兜底静态图仍可演示 |
| Tab 切换地图空白 | `invalidateSize`；`v-if` 切换时组件重建 |
| 误点「相关数据」无反应 | 需**农技员**角色；合作社仅能见首页/关于我们（路由 `requiresRole`） |
| 改 Mock 后线上仍旧数据 | 执行 `pnpm sync:mock-db` 并上传 `deploy/api_mock/` |
