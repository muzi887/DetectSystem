# 🌱原理卡：

> [!NOTE] **定义**：  
> 在前端应用中建立一个集中的错误处理机制，对所有可能的错误进行标准化、一致化的处理。

---

## 关键点

### 错误分类

1. **网络错误** (Network Errors)
2. **HTTP错误** (HTTP Errors)
3. **业务错误** (Business Errors)
4. **前端错误** (Client Errors)


---

## 代码示例
用 **Axios** 的响应[[拦截器]]来统一处理响应里的错误：
```ts
http.interceptors.response.use(
  response => response,
  error => {
    // 这里可以全局处理 401/403 等
    return Promise.reject(error)
  }
)
```
- `http.interceptors.response.use(onFulfilled, onRejected)`
    
    - `onFulfilled`（第一个参数）在请求成功（HTTP 状态码 2xx）时调用。这里写成 `response => response`，意思是**原封不动把响应传下去**，不做处理。
        
    - `onRejected`（第二个参数）在响应被拒绝（网络错误、非 2xx 状态码、超时 等）时调用。你在这里把错误传进来并可以做统一处理。
        
- `error` 对象里常见的字段（重要）：
    
    - `error.response` —— 服务器有返回（但状态非 2xx），包含 `status`、`data`、`headers` 等。
        
    - `error.request` —— 请求已经发出，但没有收到响应（可能是网络问题、被阻止、CORS、断网等）。
        
    - `error.message` —— axios 报的错误信息（例如 `Network Error`、`timeout of 5000ms exceeded`）。
        
    - `error.config` —— 发请求时的配置（可用于重试）。
- `全局处理 401/403 等` 的典型做法：
    
    - 检测 `error.response.status`，对不同状态做统一处理（401 → 强制登出/跳转登录/刷新 token；403 → 提示无权限；500 → 全局错误提示等）。
        
    - 显示通知/提示（toast、弹窗）。
        
    - 自动刷新 token（并重试原始请求）。
        
    - 记录日志或上报错误。
        
- `return Promise.reject(error)` 的意义：
    
    - 将错误继续以 rejected 状态抛出，交给调用这次请求的地方去 `catch`。如果你在拦截器里处理了错误并想让调用方认为请求成功，可以 `return someFallbackValue`（或 `return Promise.resolve(...)`）；但一般保留 `reject`，让调用方也能按需处理。
