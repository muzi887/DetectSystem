网穿透（无需服务器，适合远程演示）

**场景**：你想发给异地的朋友看，或者手机流量访问，但不想买云服务器。  
**工具**：使用 **Ngrok** 或 **Cpolar** 等工具。

1. 下载并安装 [[Ngrok]]。
2. 在电脑上正常启动你的前端(5173)、后端(5000)、数据库(3000)。
3. 打开一个新的终端，输入命令映射前端端口：
    
    ```bash
    ngrok http 5173
    ```
    
4. Ngrok 会给你生成一个公网链接（比如 `https://abcd-1234.ngrok.io`）。
5. 把这个链接发给朋友即可。
    - _注意：免费版 Ngrok 速度较慢，且链接也是临时的。_

## Authtoken（认证令牌）寻找
### 具体错误分析

- **错误代码**：`ERR_NGROK_105`
- **错误原因**：你输入的 Token 是 `cr_35sPTt5XWMPXCONSloqZAtS9r0K`。系统检测后发现这个字符串的格式完全不像是一个合法的 ngrok Authtoken。
- **通常情况**：标准的 ngrok Authtoken 通常比较长，而且往往是以数字（比如 `2`）开头的，而不是 `cr_` 开头。你可能是不小心复制了其他的 ID（比如 API Key 或者 Tunnel ID），或者复制时漏掉了一部分。

### 解决方法

你需要重新配置正确的 Token。请按以下步骤操作：

1. **获取正确的 Token**：  
    复制报错信息里给出的这个网址，在浏览器打开：  
    https://dashboard.ngrok.com/authtokens
    
2. **找到 Token**：  
    在网页上你会看到一串很长的字符（通常被掩盖了一部分，旁边有一个 "Copy" 按钮），这就是真正的 Authtoken。
    
3. **在终端重新配置**：  
    回到你的命令行（CMD 或 PowerShell），输入以下命令并回车（把 `<你的新Token>` 换成你刚才网页上复制的那一串）：
    
    ```bash
    ngrok config add-authtoken <这里粘贴你刚刚复制的Token>
    ```
    

**成功标志：**  
执行完上面那个命令后，应该会提示 "Authtoken saved to configuration file..."。然后你再运行之前的命令（比如 `ngrok http 8080`）就可以正常使用了。

## vite拦截ngrok
这个报错的意思是：**你的前端项目（Vite）出于安全考虑，拦截了 ngrok 的访问请求。**

简单说：你的网页项目默认只允许“自己人”（localhost）访问，突然来了一个陌生的网址（ngrok 的网址），它觉得不安全，所以拒绝服务。

你需要修改你的前端项目配置文件来“放行”。请按以下步骤操作：

### 解决方法

1. 在你的代码编辑器（VS Code）里，找到项目根目录下的 **`vite.config.js`** (或者 `vite.config.ts`) 文件。
2. 找到 `server` 配置项（如果没有就加上），把你的 ngrok 网址加到 `allowedHosts` 里。

**代码修改示范：**

打开 `vite.config.js`，修改成下面这样：

```javascript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue' // 注意：你的插件可能不一样，保留你原本的即可

// https://vitejs.dev/config/
export default defineConfig({
  plugins: [vue()], // 保留你原本的 plugins
  
  // 👇 重点是添加下面这一段 server 配置
  server: {
    // 方法一：允许所有的 hosts（最省事，推荐）
    allowedHosts: true, 
    
    // 或者 方法二：只允许你现在这个 ngrok 网址（比较麻烦，每次变网址都要改）
    // allowedHosts: ['trent-filtrable-phillis.ngrok-free.dev'],
  }
})
```

###以此操作后，切记：

1. **保存** `vite.config.js` 文件。
2. 去运行前端项目的那个终端（**不是**运行 ngrok 的那个窗口），按 `Ctrl+C` 停止项目。：运行 `ngrok http 5173`
3. 重新输入 `npm run dev` (或你平时启动项目的命令) **重启项目**。
4. 现在刷新浏览器，应该就可以看到页面了！

打个比方：

- **你的项目（`npm run dev`）**：就像是你家里的**电视机**，正在播放节目。
- **ngrok**：就像是一根**连接到外面的信号线**。
- **刚才修改的 `vite.config.js`**：就像是电视机的一个**设置选项**，你把“禁止外部信号接入”这个开关给关掉了。

## `304 Not Modified`

- **字面意思**：资源未被修改。
- **发生了什么**：
    1. 你的浏览器（前端）向服务器发送了一个请求（比如获取报警信息 `/api/alerts`）。
    2. 浏览器虽然发了请求，但它手里其实存了一份**旧的数据**，它顺便问了服务器一句：“老哥，这数据从上次到现在**变了没**？”
    3. 服务器检查了一下，发现数据确实没变，于是回复了 **304**：“没变！你直接用你缓存里存的那份就行，我就不重新发给你了。”

### 2. 为什么会出现这个？

这说明你的网站做得挺标准的，浏览器的**缓存机制**在起作用。

- **如果没有304**：每次刷新或请求，服务器都要把所有数据完整发一遍，浪费流量，速度慢。
- **有了304**：服务器只回一个很小的信号（几百字节），浏览器直接从本地加载数据，速度飞快。

### 3. 结合你的项目看

看这两个接口的名字：

- `/api/alerts` （报警信息）
- `/api/monitorPoints` （监测点）

这看起来像是一个**监控系统**（很符合挑战杯项目的调性）。  
通常这种网页会每隔几秒钟自动请求一次后台（轮询），看看有没有新报警。因为你现在可能没有在后台添加新数据，所以服务器一直告诉前端：“没更新，没更新，没更新（304）”。

### 总结

- **这是错误吗？** ❌ 不是。
- **需要修吗？** ❌ 不需要。
- **说明了什么？** ✅ 说明你的**前后端接口已经打通了**，而且你的浏览器能够成功访问到你的后端服务！

你可以继续复习编译原理了，你的网站运行得很健康！
