# 一步到位的总体思路（目标）

1. 快速搭好前后端两个仓库（frontend / backend），能完成登录 + 仪表盘 + 模拟监测点 + 预警流（全流程演示）。
    
2. 用 JSON Server 或 Mock 服务做假数据，前端与之联调；后端接口先做骨架（Controller + DTO + Repo），后续再接真实 DB 与模型。
    
3. 清晰的 API 规范（OpenAPI 风格），便于前后端并行开发与自动化测试。

# 必备 API 设计（最少集合，方便演示）

> 建议先用 JSON Server 实现这些路由，前端直接调用 mock 服务，后端再逐步实现同名接口。

### Auth

- `POST /api/auth/login`  
    Request: `{phone, password}`  
    Response: `{ token, user:{id,name,role} }`
    
- `POST /api/auth/register`（可选）
    

### 监测点

- `GET /api/monitor/points` → 列表（支持 area、status 过滤）
    
- `GET /api/monitor/points/{id}` → 详细（历史数据）
    
- `GET /api/monitor/points/{id}/timeseries?from=&to=` → 时序数据
    

### 预警

- `GET /api/alerts` → 预警列表（level, handled 过滤）
    
- `POST /api/alerts/{id}/handle` → 标记已处理
    

```ts
// 简单错误提示
if (err.response?.status === 401) {
  alert('手机号或密码错误')
} else if (err.response?.status === 500) {
  alert('服务器错误')
} else if (err.message?.includes('Network Error')) {
  alert('网络连接失败')
} else {
  alert('登录失败')
}
```
### 决策建议

- `GET /api/suggestions?alertId=` → 返回防治建议、物资/人员建议
    

把这些写成一个 `openapi.yaml` 会更利于团队并行（你可以后来补）。

# 前端关键代码片段（示例）

**src/services/api.ts**

```ts
import axios from 'axios'
const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE || 'http://localhost:4000'
})
// 请求拦截器：附带 token
api.interceptors.request.use(config => {
  const token = localStorage.getItem('token')
  if(token) config.headers.Authorization = `Bearer ${token}`
  return config
})
export default api
```

**Pinia store 简单示例**

```ts
import { defineStore } from 'pinia'
export const useUserStore = defineStore('user', {
  state: () => ({ token: '', info: null }),
  actions: {
    async login(phone, password) {
      const { data } = await api.post('/api/auth/login', {phone,password})
      this.token = data.token
      this.info = data.user
      localStorage.setItem('token', data.token)
    }
  }
})
```
