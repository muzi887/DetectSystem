# 宝塔面板部署排查记录：Flask 项目踩坑全解析

> [!abstract] 核心总结
> Flask 项目部署失败的核心问题通常并非代码逻辑错误，而是由三大环境因素交织导致的：**虚拟环境认知偏差**、**依赖安装错位**、以及**网络端口监听配置异常**。理清这三层关系，即可顺利跑通。

---

## 🧐 第一部分：上帝视角复盘（问题根源）

> [!bug] 阶段一：环境与依赖错位 (`ModuleNotFoundError`)
> **当时的现象**：报错提示 `No module named 'flask'`。
> **真正的凶手**：**安装环境 ≠ 运行环境**。在终端用 `pip install` 安装依赖时，装在了系统全局环境中；而宝塔或启动脚本使用的却是项目专属的虚拟环境，导致找不到包。
> **解决思路**：要么在全局环境中运行项目，要么精准进入虚拟环境的绝对路径下安装依赖。

> [!warning] 阶段二：虚拟环境认知误区
> **当时的现象**：执行 `source py-project-env/bin/activate` 后，由于目录跳转错误，导致找不到代码或 `requirements.txt`。
> **真正的凶手**：误以为“激活虚拟环境 = 进入该文件夹”。激活虚拟环境仅仅是**切换了系统当前使用的 Python 解释器**，你仍然需要在项目根目录下执行运行命令。
> **解决思路**：先 `cd` 进入项目根目录，再执行 `source` 命令激活环境。

> [!failure] 阶段三：外网访问失败与端口占用
> **当时的现象**：网页打不开，或者报错 `Address already in use: 5000`。
> **真正的凶手**：
> 1. 代码里写了多余的默认 `app.run()`，导致服务只绑定了 `127.0.0.1`，外网无法访问。
> 2. 反复启动测试导致之前的 Python 进程变成了僵尸进程，死死占用了 5000 端口。
> **解决思路**：修改代码强制绑定 `0.0.0.0`，并在重启前清剿旧进程。

## 🛠️ 第二部分：终证实操手册（SOP）

遇到 Flask 部署问题，请严格按照以下标准化流程执行：

### ⚔️ Step 1: 清理僵尸进程并释放端口
*目标：解决 `Address already in use` 报错*

打开宝塔终端，强制干掉卡死的进程：
```bash
# 1. 查找占用 5000 端口的进程
lsof -i:5000

# 2. 强行杀掉查出的进程 (替换 PID)
kill -9 <你的PID数字>
````

---

### 🛡️ Step 2: 修复网络监听配置

_目标：解决项目能跑但外网无法访问的问题_

打开项目入口文件（如 `app.py`），确保**只有一个**运行入口，且必须按照以下格式配置：

```Python
# 必须绑定 0.0.0.0 才能允许外网（宝塔/Nginx）访问
if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
```

---

### 💣 Step 3: 标准化虚拟环境与启动流程

_目标：确保依赖正确安装，且启动路径不出错_

打开终端，按顺序执行：

```Bash
# 1. 必须先进入项目真实代码目录
cd /www/wwwroot/DetectSystem/api_flask

# 2. 激活虚拟环境 (注意：不要 cd 进环境文件夹)
source py-project-env/bin/activate

# 3. 安装依赖 (此时安装必定在虚拟环境内)
pip install -r requirements.txt
# 或者单装：pip install flask flask-cors

# 4. 指定使用虚拟环境的 python 来启动项目
/www/wwwroot/DetectSystem/api_flask/py-project-env/bin/python app.py
```

> [!success] 最终验证 结合宝塔安全组放行 `5000` 端口，外网即可成功请求 Flask 接口。
