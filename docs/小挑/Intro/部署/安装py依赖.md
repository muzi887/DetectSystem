看到这个黑底白字和一大串红字的报错千万别慌！你没有做错任何事，也没有弄坏老师的服务器。

这个报错的核心罪魁祸首是那句不起眼的英文：

`/usr/bin/python3.10: No module named ensurepip`

### 🕵️‍♂️ 为什么会报这个错？

你的服务器使用的是 Ubuntu 系统。Ubuntu 为了节省系统空间，默认把系统自带 Python 的一个极其重要的底层模块（也就是用来创建虚拟环境的 `ensurepip` 和 `venv`）给“阉割”掉了。

宝塔面板在尝试为你安装 `Flask` 和 `Flask-Cors` 时，必须先创建一个隔离的虚拟环境，结果发现工具被阉割了，于是直接崩溃罢工。

_(注：之前我千叮咛万嘱咐不要用 `apt` 命令去装 `npm`，是因为宝塔有更好的 PM2 插件接管。但对于这种 **Linux 操作系统底层 Python 模块缺失**的问题，我们必须通过系统的 `apt` 命令把它补全，这非常安全，绝对不会影响服务器上的其他项目。)_

### 🛠️ 终极解决办法（1分钟搞定）

**第一步：补全系统 Python 模块**

1. 点击宝塔面板左侧的 **“终端”**。
    
2. 在终端窗口中，复制并粘贴下面这行命令，然后回车执行：
    
    Bash
    
    ```
    apt-get update && apt-get install python3.10-venv -y
    ```
    
3. 等待十几秒，看到屏幕滚动完毕，没有报错，就说明底层模块补全成功了。
    

**第二步：重新安装你的 Flask 依赖**

1. 回到你发给我的**第二张截图**的界面（Python项目管理 -> `api_flask` -> 模块）。
    
2. 先点击右上角的 **“强制刷新”**。
    
3. 然后点击 `Flask` 和 `Flask-Cors` 右侧的 **“安装”** 按钮。
    

这一次，宝塔将能够完美创建虚拟环境并把这两个包安装进去。一旦这里显示了版本号（比如 Flask 显示 3.0.x），你的 5000 端口就会瞬间启动成功！

去终端敲下那行修复命令吧，这是我们部署之旅的最后一只拦路虎了！解决后记得在浏览器里测试一下你的项目能不能完整跑通整个流程。
