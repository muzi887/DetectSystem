这是一个非常好的问题！在本地开发时，很多项目习惯把 mock 数据放在 `src` 目录下为了图方便。

但是，就像我们之前提到的，**当你运行 `npm run build` 打包之后，整个 `src` 目录（包括里面的 `mock` 文件夹）就会被完全抛弃！** 生成的 `dist` 文件夹里只有纯静态的网页文件，它是没有能力去运行 `json-server` 的。

所以，在线上部署时，我们必须把这部分“模拟后端”**强行剥离出来**，让它成为一个独立的服务。你只需要做以下简单的“搬家”工作：

### 剥离与部署步骤

**第一步：提取核心数据（本地操作）**

在你的本地电脑上，找到 `src/mock/db.json` 这个文件。**这个文件就是你模拟后端的所有“灵魂”**（里面装了所有的测试数据）。

_(注：至于那个 `server.ts`，通常只是你在本地开发时用来辅助启动 json-server 的脚本。在线上我们直接用 PM2 敲命令启动，所以不需要管这个 `server.ts`)_。

**第二步：上传到宝塔独立目录**

按照我们之前规划的“高内聚”目录结构，打开宝塔面板，进入你的模拟后端专属目录：

`/www/wwwroot/kunling_system/api_mock/`

把刚才提取出来的 **`db.json` 单独上传到这个文件夹里**。

**第三步：用 PM2 跑起来（宝塔操作）**

现在你的 `api_mock` 文件夹里有了 `db.json`，接下来让它跑在 3000 端口：

1. 打开宝塔左侧的“终端”。
    
2. 进入目录：`cd /www/wwwroot/kunling_system/api_mock/`
    
3. 确保安装了插件（如果之前没装过）：`npm install -g json-server`
    
4. 打开软件商店的 **PM2管理器**，点击“添加项目”。
    
    - **启动命令（关键）**：直接写 `json-server --watch db.json --port 3000`
        
    - 这样 PM2 就会把你的 `db.json` 变成一个真正的后端接口服务，并且永远在后台运行。
        

---

**一句话总结你的系统在线上是怎么协作的：**

虽然在本地源码里它们揉在一起，但在宝塔服务器上，它们是三个完全独立的“打工人”：

1. **Vue 前端 (`dist`)** 住在 `frontend` 文件夹，由 **Nginx** 接管。
    
2. **AI 后端 (`app.py`)** 住在 `api_flask` 文件夹，由 **Python项目管理器** 跑在 5000 端口。
    
3. **模拟后端 (`db.json`)** 住在 `api_mock` 文件夹，由 **PM2管理器** 跑在 3000 端口。
    

前端网页通过 Nginx 的反向代理，去向这俩后端的端口要数据。把 `db.json` 抽出来单独跑，思路就彻底理顺了！
