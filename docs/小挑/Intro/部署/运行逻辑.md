### 🏛️ 一、 核心组件阵列（三个服务在干嘛？）

#### 1. 前端（门面）：Vue 3 静态网站

- **状态**：代码已经被 `npm run build` 打包成了纯静态文件（存放在 `dist` 文件夹中）。
    
- **端口**：运行在服务器的 **`88`** 端口。
    
- **职责**：负责向用户展示地图、图表、登录界面，接收用户的点击和上传操作。它本身没有任何处理数据的能力，只是一个负责“发号施令”和“展示结果”的漂亮皮囊。
    

#### 2. 主后端（大脑）：Node.js 模拟接口

- **状态**：通过你手写的 `server.js` 脚本运行，背后连接着 `db.json` 作为轻量级数据库。
    
- **端口**：监听在本地的 **`3000`** 端口（并且绑定了 `0.0.0.0`）。
    
- **职责**：处理绝大部分的业务逻辑，包括**用户登录校验（发 Token）、查询监测点数据、新增或删除预警信息**等。
    

#### 3. AI 后端（特种部队）：Python Flask 接口

- **状态**：在一个专属的 Python 虚拟环境（`py-project-env`）中独立运行。
    
- **端口**：监听在本地的 **`5000`** 端口（并且绑定了 `0.0.0.0`）。
    
- **职责**：只干一件重活——**接收前端传来的作物图片，调用深度学习模型进行识别，并返回“灾害类型”和“置信度”**（供智能分析模块渲染结果）。
    

---

### 🛡️ 二、 两大守护管家（是谁在维持秩序？）

为了让这三个组件能够24小时不间断地协同工作，服务器里安排了两个“管家”：

#### 1. Nginx（交通警察 & 迎宾员）

- **静态托管**：当用户在浏览器输入 `http://82.157.234.123:88` 时，Nginx 会立刻把打包好的 Vue 页面发给用户。
    
- **路由兜底**：得益于你配置的 `try_files`，即使用户在子页面（比如 `/login`）刷新，Nginx 也不会报 404，而是聪明地交回给 Vue 处理。
    
- **反向代理（极其关键）**：当 Vue 想要向后台请求数据（比如发送 `/api/login`）时，Nginx 会像个交警一样，把这个请求**暗中转发**到服务器内部的 `3000` 端口交办，然后再把结果拿回来还给 Vue。
    

#### 2. PM2（后台保安队）

- **进程守护**：PM2 现在正死死盯着你的 Node.js (`3000` 端口) 和可能的其他脚本。如果代码不小心崩溃了，PM2 会在 1 秒内自动把它重新拉起来。
    
- **日志记录**：也就是你之前排查问题时看的那个“错误/运行日志”，它默默记录了后端接收到的每一次数据。

### 🚀 三、 动态数据流向（以“登录并上传图片”为例）

当一个农户打开你的系统并完成操作，数据是这样跑满全场的：

1. **【请求页面】**：农户访问 `...:88`，Nginx 从硬盘把网页发给浏览器。
    
2. **【发起登录】**：农户输入 `13800000000/123456` 点击登录。
    
3. **【Nginx 代理】**：前端发出 `POST /api/login`。Nginx 收到后，转发给内部的 `http://127.0.0.1:3000/login`。
    
4. **【验证发牌】**：PM2 守护下的 `server.js` 收到请求，去查阅 `db.json`。暗号对上了，生成一个 Token，顺着 Nginx 原路返回给浏览器。**（登录成功！）**
    
5. **【AI 分析】**：农户在“智能分析模块”上传了一张苹果叶片发黄的图片。
    
6. **【专属通道】**：前端直接向 `http://82.157.234.123:5000`（Flask 接口）发送图片数据。
    
7. **【得出结论】**：Python 虚拟环境中的模型进行运算，返回 `{"message": "苹果腐烂病", "置信度": "88%"}`。前端将结果渲染到屏幕上。
