# 宝塔面板部署排查记录：从 401 到登录成功

> [!abstract] 核心总结
> 本次排查的核心结论：**前端与后端核心逻辑代码完全正确（修改 0 行）**。
> 项目最初遭遇的 `401`、中间发生的 `404` 以及最后出现的 `500` 错误，根本原因均不在代码逻辑，而在于**服务器运行环境配置异常**。理顺环境后，项目即刻成功运行。

---

## 🧐 第一部分：上帝视角复盘（问题根源）

> [!bug] 阶段一：`401 Unauthorized` & 接口无响应
> **当时的现象**：前端发出了正确的账号密码，但后端要么无响应，要么乱报错（401）。
> **真正的凶手**：服务器的 `3000` 端口和 `5000` 端口一直被之前手动运行的“僵尸进程”死死占用。响应前端登录请求的根本不是最新写好的 `server.js`，而是一个卡死在后台的旧程序。
> **解决思路**：查出并强行杀死占用端口的进程，让 PM2 重新接管服务。

> [!warning] 阶段二：`404 Not Found` (页面刷新白屏)
> **当时的现象**：在浏览器地址栏直接回车，或者页面跳转时，Nginx 报错 404。
> **真正的凶手**：Vue 是单页应用（SPA），只有 `index.html`。Nginx 默认不懂 Vue 的虚拟路由，跑去服务器物理文件夹里找对应的路由文件，找不到就报错。
> **解决思路**：修改 Nginx 配置，将所有找不到的路径重定向回 `index.html`，交由 Vue Router 处理。

> [!failure] 阶段三：`500 Internal Server Error` (接口崩溃)
> **当时的现象**：接口报 500 崩溃。
> **真正的凶手**：为了看日志排查问题，在数据库变量声明之前加入了一行 `console.log('当前数据库里的 users:', db.users)`，导致 Node.js 触发 ReferenceError 致命报错。
> **解决思路**：删除/注释掉这行引起崩溃的测试代码，重启服务。

## 🛠️ 第二部分：终证实操手册（SOP）

遇到类似问题，请严格按照以下三步执行物理打击：

### ⚔️ Step 1: 终端清剿“僵尸进程”
*目标：解决 401 报错，让 PM2 重新接管核心端口*

打开宝塔面板左侧 **终端**，执行以下命令：

1. **查找占用 `3000` 端口的进程：**
```bash
lsof -i:3000
````

_(在输出的列表中找到对应的 `PID` 数字，例如 1515426)_

2. **强行杀掉该进程：**
    

Bash

```
kill -9 <你的PID数字>
```

3. **对 `5000` 端口（Python后端）执行同样的清剿：**
    

Bash

```
lsof -i:5000
kill -9 <你的PID数字>
```

4. **验证是否清理干净：** 再次运行 `lsof` 命令，若终端没有任何输出，即代表端口已彻底腾出。
    

---

### 🛡️ Step 2: 宝塔面板修复 Nginx 路由

_目标：解决 Vue 页面（SPA）刷新变成 404 Not Found 的问题_

1. 点击宝塔左侧菜单的 **网站**。
    
2. 找到前端运行的网站（跑在 `88` 端口），点击最右侧的 **设置**。
    
3. 在弹出的窗口中，点击左侧的 **配置文件**。
    
4. 找到 `location / { ... }` 代码块，在其中**精准加入以下代码**：
    

Nginx

```
try_files $uri $uri/ /index.html;
```

5. 点击 **保存**。
    

---

### 💣 Step 3: 删减致灾代码并重启 PM2

_目标：解决接口报 500 Internal Server Error 崩溃的问题_

1. 点击宝塔左侧菜单的 **文件**。
    
2. 进入 `/www/wwwroot/你的项目名/api_mock/` 目录，双击编辑 `server.js`。
    
3. 找到并**删除/注释掉**提前读取未定义变量的测试代码：
    

JavaScript

```
// console.log('当前数据库里的 users:', db.users); 
```

4. 点击编辑器左上角的 **保存**。
    
5. 点击宝塔左侧菜单的 **软件商店** -> **PM2管理器**。
    
6. 找到你的模拟后端项目（如 `json-api`），点击最右侧的 **重启**。
