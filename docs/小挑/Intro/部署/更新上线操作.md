## 一、先判断：这次要上传什么？

本次改动**主要是前端 UI**，按 [`docs/本次未提交修改说明.md`](docs/本次未提交修改说明.md)：

| 类型 | 是否需要上传 | 说明 |
|------|-------------|------|
| **前端 `dist/`** | ✅ **必须** | 页面、样式、热力图、响应式等都在里面 |
| **`deploy/api_mock/`** | ⚠️ 视情况 | 若只改 UI、**未改** `src/mock/db.json` / `server.js`，可不上传 |
| **`server/app.py`（Flask）** | ❌ 本次可跳过 | 仅删注释，不影响功能 |
| **Git 提交** | 建议先做 | 方便回滚，与上线无关 |

## 二、本地打包（Windows PowerShell）

在项目根目录 `DetectSystem` 执行：

```powershell
# 1. 安装依赖（有新包时）
pnpm install

# 2. 生产构建（会把 src/assets、public 等打进 dist）
pnpm build
```

构建成功后会有 `dist/` 目录，内含 `index.html`、`assets/` 等。

**若改过 Mock 数据**（`src/mock/db.json`），同步到部署包：

```powershell
Copy-Item src\mock\db.json deploy\api_mock\db.json -Force
```

> 线上已有演示数据时，**不要随意覆盖服务器 `db.json`**，见 [`deploy/线上故障排查笔记.md`](deploy/线上故障排查笔记.md) Step 3。

**可选：本地先验一遍**

```powershell
pnpm preview   # 预览 dist，默认 http://localhost:4173
```

另开终端跑 Mock（登录等需 API 时）：

```powershell
pnpm mock
```

## 三、上传到云端（宝塔）

服务器：**82.157.234.123**  
线上地址：**http://82.157.234.123:88**

### 3.1 上传前端（必做）

1. 宝塔 → **文件**
2. 进入：`/www/wwwroot/DetectSystem/frontend/dist/`
3. **删除或备份** 旧 `dist` 内容（至少清空 `assets/` 和 `index.html`）
4. 上传本地 **`dist/` 内全部文件**（不是上传 dist 文件夹本身，而是其内容）

目录应对应：

```
/www/wwwroot/DetectSystem/frontend/dist/
├── index.html
├── favicon.png
├── apple-touch-icon.png
└── assets/
    ├── index-xxxxx.js
    ├── index-xxxxx.css
    ├── ndvi-heatmap-xxxxx.webp
    └── ...
```

> 注意拼写是 **`frontend`**，不是 `fontend`（见故障排查笔记第七章）。

### 3.2 上传 Mock（仅 Mock 有改动时）

若同步了 `db.json` 或改过 `deploy/api_mock/server.js`：

1. 进入：`/www/wwwroot/DetectSystem/api_mock/`
2. 覆盖上传：
   - `package.json`
   - `server.js`
   - `db.json`（**确认要覆盖线上数据再传**）
3. 终端执行：

```bash
cd /www/wwwroot/DetectSystem/api_mock
npm install --registry=https://registry.npmjs.org
```

4. 宝塔 → **网站** → **Node 项目** → 找到 `api_mock` / `json-api` → **重启**

详细步骤见 [`deploy/宝塔部署-不用PM2.md`](deploy/宝塔部署-不用PM2.md) 第三～四节。

### 3.3 Flask（本次可跳过）

`server/app.py` 仅注释变更，**不必重传**。若以后改了 AI 逻辑，再更新 `/www/wwwroot/DetectSystem/api_flask/` 并重启 Python 项目。

## 四、服务器侧确认（不用改 Nginx 时）

仅更新前端 `dist` 时，**一般不用动 Nginx**。按 [`deploy/线上故障排查笔记.md`](deploy/线上故障排查笔记.md) 做快速体检：

```bash
# 前端
curl -I http://127.0.0.1:88/

# Mock
curl http://127.0.0.1:3000/monitorPoints

# 确认新文件在
ls /www/wwwroot/DetectSystem/frontend/dist/index.html
ls /www/wwwroot/DetectSystem/frontend/dist/assets/ | head
```

宝塔面板确认：

- [ ] **Node 项目** `api_mock` → 运行中（绿）
- [ ] **Python 项目** `api_flask` → 运行中
- [ ] **PM2** 里无 `json-api`（避免占 3000 端口）
- [ ] 腾讯云 + 宝塔 **安全** 均放行 **88**

## 六、推荐发布顺序（简版）

```
本地 pnpm build
    ↓
（可选）Copy-Item db.json → deploy/api_mock/
    ↓
宝塔上传 dist/* → frontend/dist/
    ↓
（Mock 有改）上传 api_mock 三文件 + npm install + 重启 Node 项目
    ↓
服务器 curl 自检 + 浏览器强刷验证
```

## 七、常见问题速查

| 现象 | 处理 |
|------|------|
| 502 整站 | 88 端口防火墙；Nginx 是否运行 |
| 502 仅登录 | Node 项目未运行；`curl 127.0.0.1:3000` |
| 404 `/api/...` | Nginx 反代丢失，见故障排查笔记 Step 5 |
| 页面能开、样式不对 | dist 未全量覆盖；强刷缓存 |
| `Cannot find module 'json-server'` | api_mock 目录 `npm install --registry=...` |
| 本机正常、外网不行 | 腾讯云防火墙未放行 88 |

更完整对照表见 [`deploy/线上故障排查笔记.md`](deploy/线上故障排查笔记.md) 第三节。

## 八、Git 提交（建议，与上线独立）

上线前建议先 commit，便于回滚：

```powershell
git add .
git commit -m "feat(ui): 统一玻璃拟态样式、接入遥感素材并完善移动端适配"
```

GitHub 推送与宝塔上传是两套流程：**服务器不拉 Git**，只认你上传的 `dist/` 和 `api_mock/` 文件。
