# 宝塔更新上线操作（通用版）

按本项目实际架构（**Nginx:88 + Node Mock:3000 + Flask:5000**），每次发布前先判断「改了什么」，再决定上传哪些目录。

**线上地址**：http://82.157.234.123:88  
**服务器路径根目录**：`/www/wwwroot/DetectSystem/`

---

## 一、先判断：这次要上传什么？

对照本次改动，勾选需要上线的部分：

| 改动类型 | 是否上传 | 上传目标 | 典型文件 / 目录 |
|----------|----------|----------|-----------------|
| 前端页面、样式、地图交互、Store | ✅ 几乎总是 | `frontend/dist/` | 本地 `pnpm build` 后的 `dist/*` |
| Mock 数据（遥感三表、监测点等） | ⚠️ 有改才传 | `api_mock/` | `db.json`（经 `pnpm sync:mock-db` 同步） |
| Mock 接口逻辑 | ⚠️ 有改才传 | `api_mock/` | `server.js`、`agriMockCore.cjs` |
| Mock 依赖变更 | ⚠️ 很少 | `api_mock/` | `package.json` → 服务器需 `npm install` |
| Flask AI 分析 | ⚠️ 有改才传 | `api_flask/` | `app.py` 等 → 重启 Python 项目 |
| Nginx 反代 | ⚠️ 极少 | 面板配置 | 一般只发版不动 |

### 三种常见发布档位

| 档位 | 适用场景 | 最小动作 |
|------|----------|----------|
| **A · 仅前端** | 只改了 `.vue` / `.ts` / 样式 / 静态图，Mock 与 Flask 未动 | `pnpm build` → 上传 `dist/*` → 强刷浏览器 |
| **B · 前端 + Mock** | 含 P1 查墒情、自定义路由、`db.json` 遥感数据等 | A + 上传 `api_mock` 相关文件 → **重启 Node 项目** |
| **C · 全栈** | 另改了 Flask AI | B + 上传 `api_flask` → 重启 Python 项目 |

> **注意**：`pnpm sync:mock-db` 只同步 `fields` / `ndviLayers` / `moistureLayers` 到 `deploy/api_mock/db.json`，**不会**复制 `server.js` / `agriMockCore.cjs`，自定义路由需手动上传。

## 二、本地准备（Windows PowerShell）

在项目根目录 `DetectSystem` 执行：

```powershell
# 1. 依赖有变更时
pnpm install

# 2. 若改过 src/mock/db.json 中的遥感三表或监测点等
pnpm sync:mock-db

# 3. 生产构建（src/assets、public 等打进 dist）
pnpm build
```

构建成功后本地应有 `dist/`（`index.html`、`assets/` 等）。

**不要随意覆盖线上 `db.json`**：若服务器上改过演示数据，上传前先确认。见 [`deploy/线上故障排查笔记.md`](../../../../deploy/线上故障排查笔记.md) Step 3。

### 可选：本地先验一遍

```powershell
# 终端 1：预览 dist（默认 http://localhost:4173）
pnpm preview

# 终端 2：Mock（登录、查墒情等需 API 时）
pnpm mock
```

本地冒烟示例（Mock 在 3000 端口时）：

```powershell
Invoke-RestMethod "http://localhost:3000/monitorPoints"
Invoke-RestMethod "http://localhost:3000/moisture/value?lat=38.99&lng=116.10"
```

## 三、上传到宝塔

### 3.1 前端 `dist/`（档位 A/B/C 均需要）

1. 宝塔 → **文件**
2. 进入：`/www/wwwroot/DetectSystem/frontend/dist/`
3. **删除或备份**旧内容（至少清空 `assets/` 与 `index.html`）
4. 上传本地 **`dist/` 内的全部文件**（不是上传 `dist` 文件夹本身）

```
/www/wwwroot/DetectSystem/frontend/dist/
├── index.html
├── favicon.png
├── apple-touch-icon.png
└── assets/
    ├── index-xxxxx.js
    ├── index-xxxxx.css
    ├── ndvi-heatmap-xxxxx.webp
    └── ...
```

> 目录名是 **`frontend`**，不是 `fontend`（见故障排查笔记第七章）。

### 3.2 Mock `api_mock/`（档位 B/C，有 Mock 改动时）

进入：`/www/wwwroot/DetectSystem/api_mock/`

按改动覆盖上传：

| 文件 | 何时必传 |
|------|----------|
| `server.js` | 新增/修改接口路由（如 `/moisture/value`） |
| `agriMockCore.cjs` | 修改登录、NDVI 摘要、查墒情等共用逻辑 |
| `db.json` | 监测点、遥感图层等数据有变（先用 `pnpm sync:mock-db`） |
| `package.json` | 依赖有变（当前仅 `json-server`） |

**`npm install` 何时需要？**

| 情况 | 要不要执行 |
|------|------------|
| 首次部署 `api_mock`，或没有 `node_modules` | ✅ 需要 |
| 报错 `Cannot find module 'json-server'` | ✅ 需要 |
| 只更新了 `server.js` / `agriMockCore.cjs` / `db.json`，`package.json` 未变 | ❌ 通常不需要 |

若需要安装依赖：

```bash
cd /www/wwwroot/DetectSystem/api_mock
npm install --registry=https://registry.npmjs.org
```

**无论是否 npm install，改完 Mock 文件后都要：**

宝塔 → **网站** → **Node 项目** → `api_mock` / `json-api` → **重启**

详细步骤见 [`deploy/宝塔部署-不用PM2.md`](../../../../deploy/宝塔部署-不用PM2.md) 第三～四节。

### 3.3 Flask `api_flask/`（档位 C，仅 AI 有改动时）

1. 覆盖上传 `/www/wwwroot/DetectSystem/api_flask/` 中变更文件（常见为 `app.py`）
2. 宝塔 → **Python 项目** → 重启 `api_flask`

前端 / Mock 发版**不必**动 Flask。

## 四、服务器侧自检

仅更新 `dist` 时，**一般不用改 Nginx**。

```bash
# 前端静态
curl -I http://127.0.0.1:88/

# Mock 基础
curl http://127.0.0.1:3000/monitorPoints

# Mock 自定义接口（有相关功能时）
curl "http://127.0.0.1:3000/moisture/value?lat=38.99&lng=116.10"

# 确认 dist 已更新
ls /www/wwwroot/DetectSystem/frontend/dist/index.html
ls /www/wwwroot/DetectSystem/frontend/dist/assets/ | head
```

宝塔面板确认：

- [ ] **Node 项目** `api_mock` → 运行中
- [ ] **Python 项目** `api_flask` → 运行中（用到智能分析时）
- [ ] **PM2** 里无额外进程占 **3000** 端口（与 Node 项目冲突）
- [ ] 腾讯云 + 宝塔 **安全** 均放行 **88**

更完整对照见 [`deploy/线上故障排查笔记.md`](../../../../deploy/线上故障排查笔记.md)。

## 六、推荐发布顺序（流程图）

```text
判断改动范围（§一）
    ↓
pnpm install（如有新依赖）
    ↓
pnpm sync:mock-db（如 db.json 遥感/监测点有改）
    ↓
pnpm build
    ↓
上传 dist/* → frontend/dist/
    ↓
（Mock 有改）上传 server.js / agriMockCore.cjs / db.json / package.json
    ↓
（仅首次或 package.json 变）api_mock 下 npm install
    ↓
重启 Node 项目（Mock 有改时必做）
    ↓
（Flask 有改）上传 api_flask + 重启 Python
    ↓
服务器 curl 自检 + 浏览器强刷（§四、§五）
```

## 七、常见问题速查

| 现象 | 处理 |
|------|------|
| 502 整站 | 88 端口防火墙；Nginx 是否运行 |
| 502 仅登录 / API | Node 项目未运行；`curl 127.0.0.1:3000` |
| 404 `/api/...` | Nginx 反代丢失，见故障排查 Step 5 |
| 查墒情失败 / 404 | 上传 `server.js` + `agriMockCore.cjs` 并重启 Node |
| 页面能开、样式不对 | `dist` 未全量覆盖；强刷缓存 |
| `Cannot find module 'json-server'` | `api_mock` 目录执行 `npm install` |
| 本机正常、外网不行 | 腾讯云防火墙未放行 88 |
| 改了 db 线上仍旧数据 | 是否执行 `sync:mock-db` 并上传 `db.json` |

## 八、Git 与上线的关系

- **建议**发版前本地 `git commit`，便于回滚；与宝塔上传无强制关系。
- **服务器不拉 Git**，只认你上传的 `dist/` 和 `api_mock/` 等文件。

```powershell
git add .
git commit -m "feat: 描述本次改动的目的"
```
