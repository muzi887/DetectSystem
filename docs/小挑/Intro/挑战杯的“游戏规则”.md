### 一、 挑战杯的“游戏规则”是怎样的？

挑战杯分为“大挑”（课外学术科技作品）和“小挑”（创业计划大赛，也叫“创青春”）。流程通常是这样的：

1. **校赛（初筛）**：
    - **形式**：交文档（申报书/商业计划书）+ 现场答辩（PPT展示）。
    - **重点**：证明你的东西“做出来了”且“有创新”。
2. **省赛（进阶）**：
    - 校赛出线的队伍参加，竞争更激烈，需要更精美的包装和更扎实的技术/商业逻辑。
3. **国赛（终极BOSS）**：
    - 全国顶级项目PK。

**你的参赛核心物料其实是三样东西：**

1. **纸质文档**（申报书/论文/计划书）：评委第一眼看的是这个。
2. **PPT**：答辩时用的。
3. **实物/Demo**（就是你的**网站**）：这是用来**“秀肌肉”**和**“证明真实性”**的。

### 二、 你的网站在比赛中起什么作用？

无论你是做“科技发明”还是“创业项目”，你的网站主要有以下三个作用：

#### 1. 证明“我做出来了”（真实性）

很多由于时间不够，项目只是“纸上谈兵”（只有PPT）。  
如果你能在答辩现场，打开你的网站，点两下功能，评委的眼神立马就不一样了。**这代表你的项目落地了，不是空想。**

#### 2. 展示“核心功能”（可视化）

- **如果你的项目是算法类**（比如“基于AI的图像识别平台”）：网站就是算法的**外壳**。你需要演示上传图片 -> 网站转圈 -> 吐出识别结果。
- **如果你的项目是信息系统类**（比如“校园二手交易平台”）：网站就是**产品本身**。你需要演示用户怎么发布商品、怎么下单。
- **如果你的项目是硬件类**（比如“智能大棚监测”）：网站就是**控制台**。你需要演示在网页上点个按钮，那边的数据变了。

#### 3. 填满申报书的篇幅

你在写申报书时，需要大量的图。**把网站的各个界面截图**，贴进文档里，配合“系统架构图”、“功能模块图”，文档看起来就会非常充实、专业。

### 三、 结合你刚才的 ngrok，现在该做什么？

你刚才折腾 `ngrok` 和 `vite.config.js`，其实就是在为**展示**做准备。

#### 场景 1：给指导老师或队友看（现在）

- **做法**：在你的电脑上运行 `npm run dev` 和 `ngrok`，把那个 `https://...` 的链接发微信给老师。
- **话术**：“老师，这是我们项目的初步原型，您手机上点开就能看，不需要安装任何东西。”（**老师会觉得你效率很高，技术很懂**）。

#### 场景 2：答辩现场（未来）

**⚠️ 听老学长的忠告：答辩现场千万不要只依赖 ngrok！**  
现场网络环境极差，万一 ngrok 连不上，你就尴尬了。你需要准备三套方案：

- **方案 A（最稳）**：**录屏**。用录屏软件把你的网站操作流程录下来，剪辑到 PPT 里或者是准备一个视频文件。评委想看演示，直接播视频，边播边解说。
- **方案 B（本地演示）**：带上你自己的笔记本电脑上去，直接用 `localhost` 演示，不需要联网。
- **方案 C（远程备用）**：如果评委非要拿出他自己的手机体验，这时候再掏出你的 `ngrok` 链接给评委扫码。

### 四、 现阶段建议

1. **截图留存**：把你做好的网站界面，尤其是比较好看的、有数据的界面，全部截图。
2. **不用太纠结技术细节**：
    - 挑战杯的评委大多不是搞前端的。他们**不看你的代码写得漂不漂亮**。
    - 他们看的是：**界面是不是看着像那么回事**（UI不丑）、**核心业务逻辑通不通**（点击能跳转）。
    - 所以，如果有些功能很难写（比如真实的支付功能），你可以 **“造假”**（Hardcode），比如点击“支付”，直接弹窗“支付成功”，不需要真的去接微信支付接口。**只要演示效果在就行。**
3. **专心复习编译原理**：
    - 网站既然能跑了，能穿透了，就先**封存**。
    - 现在的首要任务是**三天后的期末考试**。挑战杯的材料可以等考完试再慢慢写，那个周期很长。

**总结：你的网站就是你手里的“倚天剑”，是证明你实力的铁证。刚才配通了 ngrok，意味着你随时可以把这把剑拔出来给别人看，这已经领先很多只会写文档的队伍了！加油！**
