# 作物掩码与推理接入

> 解释三件事：作物掩码是什么；为何要接到真正的推理路径；假模型测试在证明什么。  
> 实现代码、类名清单、pytest 步骤见训后 Task 文档，本文不重复。

---

## 一、作物掩码

模型一次会给 **全部 23 类** 打分（小麦、玉米、番茄、水稻的病名都在同一张表里）。用户在智能分析页 **已经选了作物**。若不加约束，选「小麦」仍可能得到「稻瘟病」——那是水稻病，对用户没有意义。

**作物掩码**：softmax 之后，把「不属于当前作物」的概率改成 0，再把剩下的概率重新加总成 1。

允许留下的是：**该作物的病害 ∪ 健康**。作物代号对不上（例如旧数据里的 `peach`）则 **整表不过滤**，避免误伤。

数值直觉（不必记具体数字）：

```text
掩码前：小麦锈病 0.2，稻瘟病 0.7，健康 0.1  → 第一名是稻瘟
选 wheat：稻瘟 → 0，剩下 0.3 再除以 0.3
掩码后：小麦锈病 ≈ 0.67，稻瘟病 0，健康 ≈ 0.33  → 第一名只能是小麦病或健康
```

「掩码」= 盖住不该出现的类；「再归一化」= 让剩下的概率仍加起来为 1，置信度才可比。

## 二、接到真正的推理路径

Task 1（掩码）和 Task 2（topk / 是否需要复核）可以先写成 **纯函数**：输入一串概率，输出过滤后的概率或前几名。这时它们 **还不参与用户上传图片**。

旧推理路径只做：

```text
图片 → 模型打分 → 取最高一类 → 返回病名和置信度
```

**接到推理路径** 指插入到「真的在给图片打分」的那条链上，而不是只在测试里用手写数组演示：

```text
图片 → 模型打分 → softmax
                 → 作物掩码（Task 1）
                 → 取前 3 名 topk（Task 2）
                 → 判断是否需要复核 needs_review（Task 2）
                 → 返回病名、置信度、topk、复核标记
```

用户上传时自动走完整链条。对外旧接口仍可只取「病名 + 置信度」，命令行抽测不必改用法。

此处两个词只保留含义，规则细节见 Task 2：

| 词 | 含义 |
|----|------|
| **topk** | 不只报第一名，还带上第 2、第 3 名，便于说明「容易跟谁搞混」 |
| **复核** | 模型不够确定时打标（置信度偏低，或前两名分差过小） |

## 三、假模型测试在说什么

接入推理后，需要证明：**掩码发生在模型打分之后、取最终病名之前**。

用真实权重很难稳定制造「这张图一定被认成稻瘟」。测试因此 **不加载** `.pt`，换一个假模型：不论图片是什么，永远输出同一组原始分数（logits），并故意让 **稻瘟病那一维最高**。

若掩码没接上，结果必是「稻瘟病」。测试再带上 `crop_type=wheat`：

- 接上了 → 稻瘟被盖掉，最终只能是小麦相关类或健康
- 没接上 → 仍输出稻瘟，测试失败

这句话的意思是：**即使用户那张图被模型「看成」水稻病，只要页面选的是小麦，接口也不能返回稻瘟。** 假模型用来固定「看成稻瘟」这一前提，专门检查过滤有没有生效。

## 五、小结

| 说法 | 含义 |
|------|------|
| 作物掩码 | 按用户选的作物盖掉无关病名，再重算概率 |
| 接到推理路径 | 上传图片时自动走掩码 + topk + 复核 |
| 假模型让稻瘟最高、选 wheat 不得出稻瘟 | 固定「模型认成稻瘟」，确认小麦过滤真的挡住了它 |
