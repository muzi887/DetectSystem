# 识病模型说明

> 一份看完就能对外讲清「用什么模型、怎么训、怎么上线」的总览。  
> 基准：当前线上权重 `ml-bjj/models/pest-cls-best.pt`（2026-08-24，23 类，验证集 **94.05%**）。  
> 更细的训练步骤、掩码原理、能力边界见文末「延伸阅读」。

---

## 一、一句话

识病是 **CNN 图像分类**，不是 RNN，也不是 YOLO 检测。  
骨干网络是 **EfficientNet-B0**，框架是 **PyTorch**（不用 TensorFlow）。  
网站「智能分析」上传叶片图后，由 **Flask 加载 `.pt` 做推理**；ONNX 只是可选开关，默认关闭。

---

## 二、它是什么、不是什么

| 名称 | 角色 | 本项目 |
|------|------|--------|
| **CNN** | 卷积神经网络，擅长看图 | **是**。识病属于这一类 |
| **RNN** | 循环神经网络，擅长序列（语音、文本） | **不用** |
| **EfficientNet-B0** | CNN 里的一个具体结构 | **正在用的骨干** |
| **YOLO** | 目标检测（找框 + 类别） | 规划过，**未作主推、未上线** |
| **PyTorch** | 深度学习框架（`torch`） | **正在用** |
| **TensorFlow / Keras** | 另一套同层级框架 | **未使用** |

EfficientNet-B0 不是和 CNN 并列的第三种算法，而是 CNN 下面的具体型号。B0 是 EfficientNet 家族里最小的一档，输入 **224×224**，适合本机 / 云服务器 CPU 推理。

答辩或说明书可写：

> 识病采用基于 CNN 的 EfficientNet-B0 图像分类模型，以 PyTorch 训练与部署。

---

## 三、任务与覆盖范围

| 项目 | 说明 |
|------|------|
| 任务 | 一张叶片图 → 病名 + 置信度（另返回 top3、是否需复核） |
| 作物 | 小麦、玉米、番茄、水稻 |
| 类别数 | **23 类**（含全局 1 个「健康」） |
| 输入 | RGB 图，缩放到 224×224，ImageNet 均值/方差归一化 |
| 权重 | `ml-bjj/models/pest-cls-best.pt` |
| 元数据 | `ml-bjj/models/pest-cls-meta.json` |
| 指标 | 验证集准确率 **94.05%**（2026-08-24，CPU 训练 20 轮） |

**不要**把历史 8 类的 **98.99%** 写成当前 23 类指标。

### 23 类清单

```text
健康
小麦锈病、小麦赤霉病、小麦白粉病、小麦蚜虫为害
玉米大斑病、玉米锈病、玉米南方锈病、玉米小斑病
玉米弯孢叶斑病、玉米褐斑病、玉米瘤黑粉病、玉米茎腐病、玉米穗腐病
番茄早疫病
水稻白叶枯病、水稻褐斑病、水稻负泥虫为害、稻瘟病
水稻叶鞘腐败病、水稻叶黑粉病、水稻窄条斑病、稻颈瘟
```

「健康」是所有作物共用的一类。小麦条锈 / 叶锈 / 秆锈在标签上合并为「小麦锈病」。

## 四、框架、训练与数据划分

### 4.1 依赖

`ml-bjj/requirements.txt` 声明的是 `torch`、`torchvision`、`timm`，没有 `tensorflow`。  
骨干由 `timm.create_model("efficientnet_b0", ...)` 创建。

### 4.2 训练方式

脚本：`ml-bjj/scripts/train_cls.py`。

| 项 | 做法 |
|------|------|
| 策略 | ImageNet 预训练权重 + 本项目 23 类数据 **微调** |
| 损失 | 交叉熵 + label smoothing 0.1 |
| 优化器 | AdamW，学习率 `3e-4`，`weight_decay=1e-4` |
| 增强 | 随机水平翻转、ColorJitter |
| 保存 | 只保存 **验证准确率最高** 的 checkpoint，不是最后一轮 |

### 4.3 验证集划分

训练前先跑 `ml-bjj/scripts/prepare_from_class_folders.py`，把各类中文文件夹整理成 `ml-bjj/data/bjj_cls/train/` 与 `val/`。

| 项 | 值 |
|------|------|
| 比例 | 默认 **train 75% / val 25%**（`--val-ratio 0.25`） |
| 方式 | **按类分层**：每个病名单独洗牌再切，避免某类验证集为空 |
| 随机种子 | `42`，可复现 |
| 测试集 | **没有**独立测试集，只有 train / val |

训练脚本只读取这两个已切好的文件夹，不再现场随机切分。

### 4.4 是否过拟合

当前记录里 **没有出现验证集崩掉** 的典型过拟合：

- 第 1 轮验证准确率已约 91.4%
- 之后在约 **91.7%～94.0%** 之间波动
- 最佳在第 19 轮：**94.05%**
- 第 20 轮掉到约 91.8%，因此没用最后一轮，而用验证最好的那份权重
- 验证损失大约第 4 轮最低，之后没有持续下降

训练中用了预训练、数据增强、label smoothing、权重衰减来抑制过拟合。

需要对外说清楚的限制：

1. 脚本 **只记了验证准确率，没有记训练准确率**，看不到「训练集远高于验证集」的数值差。
2. 没有独立测试集；公开数据集近重复样本可能让验证集偏乐观。
3. 田间实拍仍须人工复核，不能把 94.05% 说成田间准确率。

## 五、上线推理：Flask 调 `.pt`

### 5.1 默认路径（当前线上）

```text
智能分析页上传叶片图并选择作物
  → Flask  ml-bjj/serving/app.py
  → torch.load(pest-cls-best.pt)
  → EfficientNet-B0 前向，得到 23 维 logits
  → softmax 变成概率
  → 按所选作物做掩码，再取第一名
  → 返回病名、置信度、topk、复核标记；非健康可写 [AI识别] 预警
```

接口入口是 `/api/analysis/image`（以及批量分析）。  
`details.engine` 为 `bjj-23`；仅当设置 `ML_BJJ_USE_MOCK=1` 时才走假推理（`mock`）。

### 5.2 ONNX（可选，默认关闭）

ONNX 是把已经训好的网络导出成另一种运行格式，**不是新模型，也不再训练**。

| 条件 | 走哪条 |
|------|--------|
| 不设环境变量（默认） | Flask + PyTorch 加载 **`.pt`** |
| `ML_BJJ_ONNX=1` 且存在 `pest-cls-best.onnx` | 前向改用 onnxruntime，后面 softmax / 掩码不变 |
| 设了开关但没有 `.onnx` 文件 | 回退继续走 `.pt` |

导出脚本：`ml-bjj/scripts/export_onnx.py`。  
线上默认 **不打开** 该开关。

## 六、作物掩码与环境规则（模型之后）

模型本身是一张 23 类「总卷」，**不会读用户选了哪种作物**。  
所以推理后还要做两步业务逻辑（不是网络结构的一部分）：

1. **作物掩码**（`crop_filter.py`）  
   softmax 之后，把不属于当前作物的病名概率置 0，剩余概率再归一化，第一名只可能来自「该作物的病 + 健康」。
2. **低置信复核**（`predict_utils.py`）  
   置信度低于 0.7，或第一名与第二名差距小于 0.10，标记需要人工复核。
3. **环境叠级**（`disease_env_rules.py`）  
   若请求带了监测点温湿墒，可对部分病害上调预警级别（例如高湿利于稻瘟 / 赤霉）。这是规则，不是第二次模型推理。

## 七、关键文件

| 路径 | 作用 |
|------|------|
| `ml-bjj/scripts/prepare_from_class_folders.py` | 按类 75/25 划分 train/val |

| `ml-bjj/serving/crop_filter.py` | 23 类清单与作物掩码 |
| `ml-bjj/scripts/export_onnx.py` | 可选导出 ONNX |

## 八、对外口径（可直接用）

- 算法：**CNN / EfficientNet-B0 图像分类**，不是 RNN，不是 YOLO。
- 框架：**PyTorch**，未使用 TensorFlow。
- 数据：按类 **75% 训练 / 25% 验证**，随机种子 42；无独立测试集。
- 指标：23 类验证集 **94.05%**；未见严重过拟合，但田间表现仍需复核。
- 部署：**Flask 默认加载 `.pt`**；ONNX 为可选加速，默认关闭。
