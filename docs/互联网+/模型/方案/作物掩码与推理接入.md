# 作物掩码与推理接入

> 按阅读顺序写：问题 → softmax → 掩码 → 接到上传图片的代码 → 用假模型验收。  
> 实现代码、23 类清单、pytest 步骤见训后 Task，本文不重复。

---

## 一、先看整条链

用户在智能分析页选作物、上传叶子照片之后，服务端按下面顺序处理。后面每一节对应其中一步。

```text
照片
  → 模型打分（logits，可正可负的裸分）
  → softmax（变成加起来 100% 的概率）
  → 作物掩码（按所选作物划掉无关病名，剩下的再凑成 100%）
  → 取前 3 名（topk），并判断要不要人工复核
  → 返回病名、置信度、topk、复核标记
```

---

## 二、问题：模型不看你选了哪种作物

用户已经选了小麦 / 玉米 / 番茄 / 水稻。模型却是一张「总卷」：23 个病名一起比，只看图长得像谁，**不会自动读作物选项**。

于是可能出现：人选了小麦，模型却说「最像稻瘟病」。稻瘟是水稻病，这个答案对用户没用。

后面两步要解决的就是这件事：**最终第一名只能来自「当前作物的病名 + 健康」。**  
但掩码不能直接改裸分，必须先经过 softmax。

---

## 三、Softmax：把裸分变成概率

模型最后一层给每个病名打一个可正可负、可大可小的分，叫 **logits（原始分数）**。例如：

| 病名 | 原始分数 |
|------|----------|
| 小麦锈病 | 1.0 |
| 稻瘟病 | 8.0 |
| 健康 | 0.5 |

这些分不能当页面上的置信度：加起来不是 100%，8.0 也不表示「80%」。

**Softmax**（代码里是 `torch.softmax`）做两件事：

1. 分数越高，变成的概率越大。
2. 全部概率加起来一定是 **1**（100%）。

上表里稻瘟 8.0 远大于另外两个，softmax 之后它会占 **几乎全部** 概率。这一步 **不管** 用户选了小麦还是水稻，只负责把 23 个裸分变成 23 个概率。

为了把后面的除法算清楚，下一节改用一张已经 softmax 过的示意表（20% / 70% / 10%）。那不是 1.0 / 8.0 / 0.5 的精确结果，只是同一类「加起来 100%」的概率表。

---

## 四、作物掩码：按作物划掉无关病名

### 4.1 划掉，再放大

假设 softmax 之后是：

| 病名 | 有多像 |
|------|--------|
| 小麦锈病 | 20% |
| 稻瘟病 | 70%（第一名） |
| 健康 | 10% |

若直接取第一名，小麦地块上就会显示水稻病。

用户选了小麦时，掩码做两步：

**划掉**：稻瘟不是小麦的病 → 改成 0（盖住，所以叫「掩码」）。

| 病名 | 划掉之后 |
|------|----------|
| 小麦锈病 | 20% |
| 稻瘟病 | **0%** |
| 健康 | 10% |

**放大**：剩下 20% + 10% = 30%。置信度习惯按满分 100% 来读，所以两边都除以 30%：

- 小麦锈病：20 ÷ 30 ≈ **67%**（新的第一名）
- 健康：10 ÷ 30 ≈ **33%**
- 稻瘟病：仍是 **0**，不可能被选中

「再归一化」就是：**划掉之后，把剩下的比例放大，让它们重新加起来等于 100%。**  
不放大的话最高分只剩 20%，看起来模型很没把握；其实只是把水稻那 70% 作废了。

和上一节对照：

| 步骤 | 干什么 | 管不管所选作物 |
|------|--------|----------------|
| Softmax | 裸分 → 概率 | 不管 |
| 作物掩码 | 划掉无关类，再凑成 100% | 管 |

### 4.2 为什么总留下「健康」

叶子也可能没病。每种作物允许留下的是：**该作物自己的病名，外加「健康」。**  
（Task 里写成「病害 ∪ 健康」，∪ 表示「再并上」。）

### 4.3 作物代号不认识时整表不动

掩码靠页面传来的 `wheat` / `corn` / `tomato` / `rice` 决定划掉谁。若传来系统不认识的值（例如旧数据里的 `peach`），不知道该划哪些，就 **一张表都不改**。宁可暂时不过滤，也不要划错。

## 五、接到真正的推理路径

第四节的掩码、以及「取前几名 / 要不要复核」，都可以先写成 **纯函数**：输入一串概率，输出过滤后的表或前几名。这时它们还只在测试里用手写数字演示，**用户上传图片时走不到**。

旧路径：

```text
图片 → 模型打分 → 取最高一类 → 只返回病名和置信度
```

**接到推理路径** 就是插进「真的在给图片打分」的那条链（也就是第一节那张图），上传时自动跑完。对外旧接口仍可只取「病名 + 置信度」，命令行抽测不必改用法。

接入时一并带上的两个结果（规则细节见 Task 2）：

| 词 | 含义 |
|----|------|
| **topk** | 除第一名外还带第 2、第 3 名，便于说明「容易跟谁搞混」 |
| **复核** | 置信度偏低，或前两名分差过小，则提示建议人工看一眼 |

## 六、假模型测试在证明什么

要证明的是：掩码发生在 **打分之后、取最终病名之前**。

真实权重很难稳定制造「这张图一定被认成稻瘟」，测试因此不加载 `.pt`，换一个假模型：不论图片是什么，永远输出同一组 logits，并故意让稻瘟那一维最高（第三节的 1.0 / 8.0 / 0.5）。Softmax 之后第一名必是稻瘟。

然后再带上 `crop_type=wheat`：

- 掩码接上了 → 稻瘟被划掉，最终只能是小麦病或健康
- 没接上 → 仍输出稻瘟，测试失败

一句话：**即使用户那张图被模型「看成」水稻病，只要页面选的是小麦，接口也不能返回稻瘟。**  
假模型用来固定「看成稻瘟」这一前提，专门检查过滤有没有接到真路径上。

## 八、小结

| 说法 | 含义 |
|------|------|
| Softmax | 把各类裸分变成加起来为 100% 的概率 |
| 作物掩码 | 按用户选的作物盖掉无关病名，再重算概率 |
| 接到推理路径 | 上传图片时自动走掩码 + topk + 复核 |
| 假模型让稻瘟最高、选 wheat 不得出稻瘟 | 固定「模型认成稻瘟」，确认小麦过滤真的挡住了它 |
