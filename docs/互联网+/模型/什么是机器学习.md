# 什么是机器学习

> 本文档面向 **零基础读者**，用通俗语言解释机器学习的基本概念，并说明它在本项目（作物灾害智慧监测预警系统）中是如何应用的。  
> 若你已了解概念、想直接动手训练模型，请阅读 [`AI模型训练说明.md`](./AI模型训练说明.md)。

---

## 一、一句话定义

**机器学习（Machine Learning，简称 ML）** 是让计算机 **从数据中自动学习规律**，而不是由程序员把每一条规则都写死在代码里。

传统编程：

```text
人写规则 → 程序按规则处理输入 → 得到输出
```

机器学习：

```text
人准备数据和目标 → 程序从样本中归纳规律 → 遇到新数据时自动判断
```

## 二、用一个生活例子理解

### 2.1 教小孩认苹果

| 方式 | 做法 | 特点 |
|------|------|------|
| **传统编程** | 你写规则：「红色、圆形、有果柄 → 苹果」 | 规则一多就写不完；遇到青苹果、蛇果容易出错 |
| **机器学习** | 你给他看 1000 张图，每张都告诉他「这是/不是苹果」 | 他自己总结出「颜色、形状、纹理」等组合特征，泛化能力更强 |

机器学习的核心不是「记住每一张图」，而是 **学到可迁移的模式**——看到没见过的苹果，也能大概率认对。

### 2.2 对应到本项目

在本系统的 **智能分析** 功能中：

1. 用户上传一张作物叶片或受害部位的照片；
2. AI 模型（已训练好的 `.pt` 权重文件）读取图像；
3. 输出 **病虫害名称 + 置信度**（例如「小麦锈病 96.3%」）。

这里的模型，就是通过大量「图片 + 正确标签」训练出来的，相当于一个 **看过很多病例的识别助手**。

## 三、机器学习的基本流程

```text
① 收集数据（图片、传感器读数、历史记录等）
      ↓
② 标注数据（告诉机器「正确答案」是什么）
      ↓
③ 选择模型结构（如 EfficientNet、决策树等）
      ↓
④ 训练（让模型反复学习，调整内部参数）
      ↓
⑤ 验证与测试（用没见过的数据检验效果）
      ↓
⑥ 部署使用（接入网站、API 或移动端）
      ↓
⑦ 持续迭代（补充新样本、重新训练、提升准确率）
```

在本项目中，步骤 ①～⑤ 对应 `ml-bjj/scripts/` 下的数据整理与训练脚本；步骤 ⑥ 对应 `ml-bjj/serving/` 推理服务与网站「智能分析」页。

## 四、常见学习类型

| 类型 | 含义 | 典型场景 | 本项目示例 |
|------|------|----------|------------|
| **监督学习** | 每条训练数据都有标准答案（标签） | 图像分类、病害识别 | 上传叶片图 → 输出病虫类别 |
| **无监督学习** | 只有数据、没有标签，机器自行发现结构 | 聚类、异常检测 | 暂未作为主路径使用 |
| **强化学习** | 通过「试错 + 奖惩」学习策略 | 游戏 AI、机器人控制 | 暂未使用 |

当前系统的病虫害识别属于 **监督学习中的图像分类任务**。

## 五、几个关键概念

### 5.1 特征（Feature）

模型做判断所依据的信息。  
对图像分类而言，特征可以是边缘、颜色分布、纹理等——现代深度学习会 **自动提取**，不必人工逐条设计。

### 5.2 模型（Model）

一组数学函数 + 可调参数，用来把输入映射到输出。  
训练完成后保存为权重文件（如 `pest-cls-best.pt`），推理时加载即可。

### 5.3 训练（Training）

用标注数据反复调整模型参数，使预测结果尽量接近真实标签。  
可理解为 **「刷题」**：题目是图片，答案是病虫名称，练多了就会做新题。

### 5.4 微调（Fine-tuning）

在 **已有预训练模型**（如在 ImageNet 上练过的 EfficientNet）基础上，用本项目的小数据集继续训练。  
好处：数据量不大时也能较快达到可用效果，不必从零开始。

### 5.5 过拟合与泛化

| 概念 | 含义 |
|------|------|
| **过拟合** | 模型把训练集「背」得太死，新数据表现变差 |
| **泛化** | 模型学到通用规律，对新样本也能正确判断 |

通过划分 **训练集 / 验证集 / 测试集**、数据增强、早停等手段，可以抑制过拟合、提升泛化。

### 5.6 准确率与置信度

| 指标 | 含义 |
|------|------|
| **准确率（Accuracy）** | 在测试集上预测正确的比例，衡量模型整体水平 |
| **置信度（Confidence）** | 单次预测时模型对结果的确信程度（0～100%） |

注意：置信度高不等于一定正确；低置信度结果应提示人工复核。

## 六、机器学习 vs 传统规则 vs 深度学习

```text
传统规则引擎          机器学习              深度学习（ML 的一个分支）
─────────────────────────────────────────────────────────────────
if 温度>30 and 湿度>80   从大量样本中学习      用多层神经网络自动
   then 高发病风险        统计/决策规律          提取复杂特征（如图像）
```

| 对比项 | 规则引擎 | 机器学习（本项目 AI 部分） |
|--------|----------|----------------------------|
| 知识来源 | 专家手工编写 | 数据驱动自动学习 |
| 适用场景 | 逻辑清晰、条件有限 | 模式复杂、难以穷举规则（如叶片病害视觉差异） |
| 可解释性 | 高（每条规则可读） | 相对较低（需额外解释工具） |
| 维护方式 | 改规则 | 补充数据、重新训练 |

本系统中 **智慧决策** 里的气象—灾害关系，当前以 **规则链** 为主（见 [`../网站/规则链建模与实现方案.md`](../网站/规则链建模与实现方案.md)）；**图像病虫害识别** 则采用 **深度学习分类模型**。两者互补，并非互相替代。

```text
DetectSystem
├── ml-bjj/                    # 机器学习子项目

                                                      ↓
                                            可联动防治知识库（TreatmentGuide）
```

## 八、什么时候适合用机器学习？

适合：

- 问题模式复杂，难以用少量 if-else 描述（如叶片病斑形态）；
- 有足够数量、质量可接受的数据；
- 允许一定误差，并有人工复核机制。

不太适合：

- 规则极少且完全确定（如「pH < 5 则报警」）；
- 几乎没有历史数据或标注成本过高；
- 必须 100% 可解释、可审计的强合规场景（需结合规则或专用解释方案）。

## 十、小结

| 要点 | 说明 |
|------|------|
| **本质** | 从数据中自动学习规律，用经验替代手写规则 |
| **本项目 AI** | 监督学习 + 图像分类，识别京津冀主要作物病虫害 |
| **产出物** | 训练好的权重文件（`.pt`）+ 推理服务 |
| **与规则引擎** | 视觉识别用 ML，气象预警等用规则链，各取所长 |

机器学习不是魔法，而是 **「数据 + 算法 + 算力」** 的系统工程。理解基本概念后，可按 [`AI模型训练说明.md`](./AI模型训练说明.md) 动手体验完整流程。
