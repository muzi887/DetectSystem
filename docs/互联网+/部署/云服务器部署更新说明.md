# 云服务器部署更新说明（互联网＋）

> 面向日常发版：本地改完代码后，如何把变更更新到腾讯云宝塔服务器。  
> **现行架构（2026-08-22）：Nginx:88 + Flask:5000 + MySQL `detect_system`。** 停掉 Node Mock :3000。  
> 本地启动见 [`../网站/项目启动说明.md`](../网站/项目启动说明.md)。  
> 迁库方案见 [`../网站/方案/Flask-MySQL替换Mock方案.md`](../网站/方案/Flask-MySQL替换Mock方案.md)。

**服务器根目录**：`/www/wwwroot/DetectSystem/`

## 一、线上架构速览

```text
浏览器  http://82.157.234.123:88
    │
    ├─ 静态页 ──────────►  Nginx → frontend/dist/
    ├─ /api/analysis/* ──►  Nginx → 127.0.0.1:5000（Flask 识病，路径保留 /api）
    ├─ /api/treatments/* ►  Nginx → 127.0.0.1:5000
    └─ /api/* ───────────►  Nginx → 127.0.0.1:5000/ （去掉 /api 前缀 → /login、/alerts）
                              Flask 再连本机 MySQL detect_system
```

| 组件 | 端口 | 服务器路径 | 托管方式 |
|------|------|------------|----------|
| Vue 前端 | **88** | `/www/wwwroot/DetectSystem/frontend/dist/` | Nginx 静态站 |
| Flask 业务+识病 | **5000** | `ml-bjj/serving` | 宝塔 Python；环境变量 `DATABASE_URL=mysql+pymysql://detect_system:<密码>@127.0.0.1:3306/detect_system` |
| MySQL | 3306 | 宝塔库 `detect_system` | 勿对公网浏览器开放 |

Nginx 示例：

```nginx
location /api/analysis/ { proxy_pass http://127.0.0.1:5000; }
location /api/treatments/ { proxy_pass http://127.0.0.1:5000; }
location /api/ {
    proxy_pass http://127.0.0.1:5000/;
}
```

建表：在服务器设好 `DATABASE_URL` 后，于 `ml-bjj/serving` 执行 `alembic upgrade head`，再 `python ml-bjj/scripts/import_db_json.py`。备份用 `mysqldump`。宝塔 **停止 Node 项目 api_mock**。

下文「档位 B 上传 api_mock」仅在紧急回退 `pnpm mock:legacy` 时使用。

### AI 目录约定

当前 README / 历史部署常用路径为 `api_flask/`。互联网＋真实推理代码在仓库的 `ml-bjj/serving/`。

| 情况 | 做法 |
|------|------|
| Python 项目仍指向 `api_flask/` | 把 `ml-bjj/serving` 所需文件（及权重）同步进该目录，或改启动文件指向新入口后重启 |
| 已单独部署 `ml-bjj` | 更新 `serving/`、`models/pest-cls-best.pt`、`requirements.txt` 后重启 Python 项目 |

无论目录名是什么，**对外端口仍是 5000**，Nginx 的 `/api/analysis/` 反代不变。

## 二、先判断：这次要上传什么？

| 改动类型 | 是否上传 | 上传目标 | 典型文件 |
|----------|----------|----------|----------|
| 前端页面、样式、Store、知识库静态页 | ✅ 几乎总是 | `frontend/dist/` | 本地 `pnpm build` 后的 `dist/*` |
| Mock 数据（监测点、遥感、预警等） | ⚠️ 有改才传 | `api_mock/` | `db.json`（先 `pnpm sync:mock-db`） |
| Mock 接口逻辑 | ⚠️ 有改才传 | `api_mock/` | `server.js`、`agriMockCore.cjs` |
| Mock 依赖 | ⚠️ 很少 | `api_mock/` | `package.json` → 服务器 `npm install` |
| AI 推理代码 / 权重 | ⚠️ 有改才传 | AI 目录（`api_flask` 或 `ml-bjj`） | `app.py`、`inference.py`、`pest-cls-best.pt` |
| Nginx 反代 | ⚠️ 极少 | 面板配置 | 一般只发版不动 |

### 三种常见发布档位

| 档位 | 适用场景 | 最小动作 |
|------|----------|----------|
| **A · 仅前端** | 只改 `.vue` / `.ts` / 样式 / 防治知识库前端展示 | `pnpm build` → 上传 `dist/*` → 强刷 |
| **B · 前端 + Mock** | 改了接口、`db.json`、智慧决策 Mock 数据等 | A + 上传 `api_mock` → **重启 Node** |
| **C · 含 AI** | 换了权重、改了 `ml-bjj/serving` | B（若有）+ 上传 AI 文件 → **重启 Python** |

## 三、本地准备（Windows PowerShell）

在项目根目录 `DetectSystem`：

```powershell
# 1. 依赖有变更时
pnpm install

# 2. 若改过 src/mock/db.json（遥感三表、监测点等）
pnpm sync:mock-db

# 3. 生产构建
pnpm build
```

构建成功后本地应有 `dist/`（`index.html`、`assets/` 等）。

> `pnpm sync:mock-db` 只同步约定字段到 `deploy/api_mock/db.json`，**不会**复制 `server.js` / `agriMockCore.cjs`；自定义路由需手动对照上传。

可选本地预览：

```powershell
pnpm preview    # 终端 1：预览 dist
pnpm run mock   # 终端 2：Mock
# 智能分析还需：ml-bjj\.venv\Scripts\Activate.ps1 后 python ml-bjj\serving\app.py
```

## 四、上传到宝塔

### 4.1 前端 `dist/`（档位 A/B/C）

1. 宝塔 → **文件** → `/www/wwwroot/DetectSystem/frontend/dist/`
2. **删除或备份**旧内容（至少清空 `assets/` 与 `index.html`）
3. 上传本地 **`dist/` 内的全部文件**（不要再套一层 `dist` 文件夹）

```text
/www/wwwroot/DetectSystem/frontend/dist/
├── index.html
├── favicon.png
└── assets/
    ├── index-xxxxx.js
    ├── index-xxxxx.css
    └── ...
```

> 目录名是 **`frontend`**，不是 `fontend`。

### 4.2 Mock `api_mock/`（档位 B/C）

进入：`/www/wwwroot/DetectSystem/api_mock/`

| 文件 | 何时必传 |
|------|----------|
| `server.js` | 新增/修改接口路由 |
| `agriMockCore.cjs` | 登录、查墒情等共用逻辑有变 |
| `db.json` | 监测点、遥感等数据有变 |
| `package.json` | 依赖有变 |

本地对应目录：`deploy/api_mock/`。

```bash
# 仅当首次部署或 package.json 变更时
cd /www/wwwroot/DetectSystem/api_mock
npm install --registry=https://registry.npmjs.org
```

**Mock 文件有改后必做**：宝塔 → **网站** → **Node 项目** → `api_mock` / `json-api` → **重启**。

### 4.3 AI 推理（档位 C）

本地源：

| 本地路径 | 作用 |
|----------|------|
| `ml-bjj/serving/app.py` | HTTP 入口 |
| `ml-bjj/serving/inference.py` | 加载权重、推理 |
| `ml-bjj/models/pest-cls-best.pt` | v3 权重（体积大，换模型时必传） |
| `ml-bjj/requirements.txt` | 依赖清单（有新增包时上传并重装） |

操作：

1. 覆盖上传到服务器当前 Python 项目目录（`api_flask/` 或已部署的 `ml-bjj/`）
2. 若改了依赖：在该目录虚拟环境中 `pip install -r requirements.txt`
3. 宝塔 → **Python 项目** → **重启**

生产进程（Windows / 宝塔）建议改 waitress，不要用 Flask 自带 `app.run`：

```text
python ml-bjj/serving/serve.py
```

Linux 可选 gunicorn：

```text
gunicorn -w 2 -b 0.0.0.0:5000 --chdir ml-bjj/serving app:app
```

本地调试仍可用 `python ml-bjj/serving/app.py`。换权重后必须重启，否则仍加载旧 `.pt`。

前端 / 仅 Mock 发版**不必**动 AI。

勿再启动仓库根目录旧 Mock：`server/app.py`（伪随机结果）。

## 五、服务器侧自检

仅更新 `dist` 时，一般**不用改 Nginx**。

```bash
# 前端
curl -I http://127.0.0.1:88/

# Mock
curl http://127.0.0.1:3000/monitorPoints

# AI（有改动时）
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:5000/api/analysis/health
# 或按你线上实际 health 路径调整；也可用上传测试图验证

ls /www/wwwroot/DetectSystem/frontend/dist/index.html
ls /www/wwwroot/DetectSystem/frontend/dist/assets/ | head
```

面板核对：

- [ ] Node 项目 `api_mock` → 运行中
- [ ] Python 项目（AI）→ 运行中（演示智能分析时）
- [ ] **PM2** 未再占 **3000**（与 Node 项目冲突）
- [ ] 腾讯云安全组 + 宝塔 **安全** 均放行 **88**

Nginx 关键片段（有 `/home` 404 或反代异常时检查）：

```nginx
location /api/analysis/ {
    proxy_pass http://127.0.0.1:5000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}

location /api/ {
    rewrite ^/api/(.*)$ /$1 break;
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}

location / {
    try_files $uri $uri/ /index.html;
}
```

网站根目录须指向：`/www/wwwroot/DetectSystem/frontend/dist`

## 七、推荐发布顺序

```text
判断改动范围（§二）
    ↓
pnpm install（如有新依赖）
    ↓
pnpm sync:mock-db（如 mock 数据有改）
    ↓
pnpm build
    ↓
上传 dist/* → frontend/dist/
    ↓
（Mock 有改）上传 api_mock 相关文件 → 必要时 npm install → 重启 Node
    ↓
（AI 有改）上传 serving / 权重 → 必要时 pip install → 重启 Python
    ↓
服务器 curl 自检 + 浏览器强刷（§五、§六）
```

## 八、常见问题速查

| 现象 | 处理 |
|------|------|
| 502 整站 | 查 88 防火墙、Nginx 是否运行 |
| 502 仅登录 / API | Node 未运行；`curl 127.0.0.1:3000` |
| `/home` 404 | 缺 `try_files` 或根目录不是 `frontend/dist` |
| 智能分析超时 | Python 未启或权重路径错误；看 Python 项目日志 |
| `Cannot find module 'json-server'` | `api_mock` 下 `npm install` |
| 换了 `.pt` 仍是旧模型 | 未重启 Python 项目 |
| 本机正常、外网不行 | 腾讯云安全组未放行 88 |
| 改了 db 线上仍旧 | 是否 `sync:mock-db` 并上传 `db.json`、是否重启 Node |

## 九、Git 与上线的关系

- 建议发版前本地 `git commit`，便于回滚；**与宝塔上传无强制关系**。
- **服务器不拉 Git**，只认你上传的 `dist/`、`api_mock/`、AI 目录文件。

git add .
git commit -m "feat: 描述本次改动的目的"
