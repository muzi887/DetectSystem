# 规则链 2.0 调度总线 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Mock:3000 落地三条规则链 + 60s 调度：持续超标才写 `[自动预警]`，扫描 7 日预报写 `[极端天气]`，凑分后写 `[虫情风险]` 草稿，决策页按前缀给建议。

**Tech Stack:** Vue 3、json-server 0.17、tsx、Node `node:test`（`pnpm exec tsx --test`）。不新增 vitest。

**Spec:** [`规则链建模与实现方案.md`](../方案/规则链建模与实现方案.md) 全文。前置：P0–P3 已在 `main`（识病闭环与 Flask `env_context`）。`fields.id` 现网是字符串（`xiongxian`），本计划 **`fieldId: string`**，不要改成 number。

- 不上 Django/Spring；不训模型；不改智能分析三列布局。
- 不实施 WebSocket；前端继续 HTTP 轮询 `alerts`。
- 阈值数字必须与方案一致：墒情 hint&lt;25 / alert&lt;15；气温 hint&gt;32 / alert&gt;38；涝渍 alert&gt;80；耐受 hint 30 min / alert 10 min。

- 链 3 高风险默认 `draft: true`，经 `POST /alerts/:id/publish` 才进待办列表（列表默认过滤 `draft !== true`）。
- 开发改了 `src/mock/db.json` 后跑 `pnpm run sync:mock-db`，并把 `syncKeys` 扩到新表。
- 测试：`pnpm exec tsx --test src/utils/alertRules.test.ts`（及后文各 test 文件）；前端 `pnpm exec vue-tsc --noEmit`。
- Flask / `disease_env_rules.py` / P3 **禁止**在本计划改动。

```ts
export const DEFAULT_THRESHOLD_PROFILE: ThresholdProfile = { /* 方案 3.2 数字 */ }

export function evaluateReading(...) {
  const nextStates: RuleState[] = []
  const alertsToCreate: NewAlert[] = []
  const hits: RuleHit[] = []
  for (const hit of detectHits(reading, profile)) {
    hits.push(hit)
    const prev = states.find((s) => s.pointId === reading.pointId && s.ruleId === hit.ruleId)
    const startedAt = prev && prev.level === hit.level ? prev.startedAt : now.toISOString()
    const elapsed = (now.getTime() - Date.parse(startedAt)) / 60000
    const alertEmitted = Boolean(prev?.alertEmitted && prev.level === hit.level)
    const state: RuleState = {
      pointId: reading.pointId,
      ruleId: hit.ruleId,
      level: hit.level,
      startedAt,
      lastSeenAt: now.toISOString(),
      alertEmitted
    }
    if (elapsed >= hit.durationMinutes && !state.alertEmitted) {
      alertsToCreate.push({
        pointId: reading.pointId,
        fieldId: null,
        level: mapRuleLevel(hit.level),
        message: buildEnvAlertMessage('POINT', hit, Math.floor(elapsed)), // POINT 由 Task 2 替换为站名
        time: now.getTime(),
        handled: false,
        source: 'auto',
        ruleId: hit.ruleId,
        chain: 'env',
        draft: false
      })
      state.alertEmitted = true
    }
    nextStates.push(state)
  }
  return { hits, nextStates, alertsToCreate }
}
```

`detectHits`：`soilVwc < alert` 优先于 hint；`airTemp > alert` 优先于 hint；`soilVwc > 80` → `waterlogging` 仅 alert。读数正常的规则不进入 `nextStates`（即清除）。

`buildEnvAlertMessage`：`soilVwc` / `waterlogging` 用「土壤湿度 …%」句式；`airTemp` 用「气温 …℃ 超过告警阈值」句式（方案 3.4）。

在 `evaluateReading` 增加可选参数 `pointName = 'POINT'`，测试里对 `alertsToCreate[0].message` 用 `buildEnvAlertMessage` 断言即可；实现里创建 alert 时调用 `buildEnvAlertMessage(pointName, hit, elapsed)`。
