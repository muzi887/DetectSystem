## 一、为什么要单独写这份方案

`2.0-功能扩展规划.md` 是产品级总纲；AI 与知识库链路已在 7 月完成。剩余工作集中在 **「感知 → 规则 → 预警 → 决策」的非 AI 闭环**，且与现有 V1.0.4 代码高度耦合——适合在 Mock 层增量扩展，而非推倒重来。

| 维度 | V1.0.4 现状 | 2.0 目标 | 本方案策略 |
|------|-------------|----------|------------|
| 预警 | 人工新建 + 单阈值着色 | 双阈值 + 耐受时间 + 自动入库 | 复用 `evaluateDisasterRules`，加状态机 |
| 气象 | 快照卡片 | 7 日预报 + 极端天气 | Mock 预报表 + 可选和风 API |
| 传感 | `weatherReadings` 单点快照 | 历史曲线、多站对比 | 扩展时序表 + ECharts |
| 遥感 | 多时相 NDVI、墒情热力图 | 风险规则 + 地块高亮 | 规则引擎，不接 ML |
| 自主性 | 手动刷新 | 定时评估 + 自动预警 | Mock 调度器 `setInterval` |

**竞赛演示原则**：Mock 数据 + 规则引擎即可闭环；真实设备/API 作为「可切换数据源」，答辩时注明数据来源。

## 四、分模块实现方案

### 4.1 §3.1 田间检测（环境感知 + 双阈值预警）

#### 4.1.1 目标

- 空气/土壤指标支持**历史趋势**（不只快照）
- **双阈值 + 耐受时间**自动产生分级预警
- 农技员可配置阈值（合作社只读）
- 与 `WarningSystem.vue`、`alertLevel.ts` 等级统一

#### 4.1.2 数据模型扩展（`db.json`）

```json
{
  "thresholdProfiles": [
    {
      "id": 1,
      "pointId": 1,
      "crop": "wheat",
      "growthStage": "jointing",
      "hint": {
        "soilVwcMax": 25,
        "airTempMax": 32,
        "durationMinutes": 30
      },
      "alert": {
        "soilVwcMax": 15,
        "airTempMax": 38,
        "durationMinutes": 10
      },
      "updatedAt": "2026-07-12T10:00:00+08:00",
      "updatedBy": "agronomist"
    }
  ],
  "sensorReadings": [
    {
      "id": 1,
      "pointId": 1,
      "recordedAt": "2026-07-12T09:00:00+08:00",
      "airTemp": 33.2,
      "airRh": 38.7,
```

> `ruleState` 存耐受计时；也可放内存（重启丢失），竞赛演示够用。

#### 4.1.3 规则引擎（核心）

新建 `src/utils/alertRules.ts`，统一客户端展示与服务端评估：

```typescript
// 伪代码结构
export type RuleLevel = 'hint' | 'alert' | 'normal'
export type AlertLevel = 'low' | 'medium' | 'high' | 'warning' | 'critical'

export function evaluateReading(
  reading: SensorSnapshot,
  profile: ThresholdProfile,
  state: RuleState[]
): { triggered: RuleHit[]; nextState: RuleState[] }

export function mapRuleToAlertLevel(level: RuleLevel): AlertLevel {
  // hint → medium/warning（黄）
  // alert → high/critical（红）
}
```

**耐受逻辑**：

```text
读数超 hint 阈值 → 记录 startedAt
持续 < durationMinutes → 不产预警
持续 ≥ durationMinutes 且未发过同规则预警 → POST /alerts（source: auto）
读数恢复正常 → 清除 ruleState
```

#### 4.1.4 API 设计

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/field-sensors/:pointId/readings?from=&to=` | 历史时序（Mock 可按 `sensorReadings` 过滤或合成） |
| GET | `/field-sensors/:pointId/thresholds` | 读取阈值配置 |
| PUT | `/field-sensors/:pointId/thresholds` | 农技员更新（校验 role） |
| POST | `/disasterRules/evaluate` | **扩展现有**：加入 profile + 耐受 + 可选 `persistAlert: true` |
| POST | `/alerts/evaluate-all` | **新增**：遍历所有监测点，批量评估（供调度器调用） |

`agriMockCore.cjs` 中 `evaluateDisasterRules` 改造要点：

1. 读取 `thresholdProfiles`（无则用默认 25/15、32/38）
2. 对比当前 `monitorPoints` 或 `weatherReadings`
3. 维护 `ruleState`，达标则 `db.alerts.push(...)` 并写 `source: 'auto'`

#### 4.1.5 前端改动

| 文件 | 改动 |
|------|------|
| `stores/data.ts` | 新增 `fetchSensorReadings`、`fetchThresholds`；`startAlertPolling()` 每 60s 调 `/alerts/evaluate-all` |
| `RelatedData.vue` 传感器 Tab | 由「预警计数图」改为 **温湿度/墒情 7 日折线**（调 `/field-sensors/.../readings` 或 `/soilMoisture/trend`） |
| `MapVisualization.vue` | 可选：侧边栏显示选中站实时读数；状态点颜色改调 `alertRules.ts` |
| `WarningSystem.vue` | 列表增加 `source` 列（自动/手动）；筛选「自动预警」 |
| **新建** `ThresholdSettings.vue` 或嵌入相关数据页 | 农技员编辑阈值表单，PUT 接口 |

#### 4.1.6 验收

- [ ] 雄县站（土壤 12%）持续 10 min 后自动产生 **high/critical** 预警，无需人工新建
- [ ] 瞬时抖动（单次读数超标）**不**触发预警
- [ ] 预警列表可区分自动/手动来源

## 九、风险与降级

| 风险 | 应对 |
|------|------|
| 真实气象 API 无 Key | 使用 Mock 预报，PPT 标注「可接和风/彩云」 |
| 耐受计时重启丢失 | 竞赛演示前启动 Mock 服务后等待 10 min，或预制 `ruleState` |
| 自动预警过多 | 调大 `durationMinutes` 或演示前清空 `alerts` |
| 与 AI 预警混淆 | `source` + `message` 前缀规范 |
