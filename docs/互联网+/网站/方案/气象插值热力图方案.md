## 一、这句话在说什么

规划里的 **❌ 插值热力图** 不是「地图上还没有彩色图」。

相关数据页已经有两类「看起来像热力图」的东西：

| 现有 | 数据从哪来 | 是不是插值 |
|------|------------|------------|
| NDVI / 土壤墒情图层 | 预先做好的 WebP，`L.imageOverlay` 贴到地块 bounds | **否**。是遥感栅格，不是站点算出来的 |
| 监测点圆点颜色 | `droughtIndex(soilVwc, dryDays)` 给 **每一个站** 上色 | **否**。只有点，点与点之间是空白 |

**插值热力图**要的是：只有河间、雄县、栾城等几个站有气温/降水/墒情数字 → 把站与站 **中间没测的地方估出来** → 铺成一片连续色块。  
「插值」= 用周围站的值填空；「热力图」= 按高低上色。规划原文写的是 **降水 / 气温格点**。

现在 Mock 站点还跨京津冀和东北，全图一张面会把黑龙江和河间连成一片，答辩讲不清。方案必须 **按当前区域裁剪**。

## 二、三种做法（选推荐）

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| A. 预生成一张气温/降水 PNG，当 NDVI 贴 | 美工或脚本出图，`RemoteSensingMap` 同款 `imageOverlay` | 半天能见；不写算法 | **不是插值**；换种子数字图不变；评委一问就穿 | 只当应急截图，不作为 2.0 交付 |
| **B. 浏览器 IDW 格点 + Canvas 贴图** | 纯函数把当前区域站点做成小格网，画成图再 `L.imageOverlay` | 数字变、色块变；不改 Mock 协议；可单测 | 站很少时面很「糊」；不是气象局克里金 | **采用** |
| C. 继续只给点上色 | 维持 `useMonitorMarkers` | 零工时 | 规划 ❌ 永远在；讲不出「区域分布」 | 竞赛来不及再选 |

**B 的产品行为：**

1. 实时监测地图增加图层开关：「干旱指数面」默认关；打开后在 **当前区域**（京津冀 / 东北四省）包络矩形内出现半透明色块。  
2. 色块跟站点走：Mock 60s tick 改了墒情/无雨日，下一轮渲染面一起变。离线站不参与插值（与灰点规则一致）。  
3. 点击仍是站点抽屉，不在色块上查格点值（避免和 GIS「点哪里查墒情」抢交互）。  
4. 图例：与圆点同一套红/橙阈值（干旱指数 ≥70 / ≥40），旁边写一句「由站点插值，非卫星反演」。

首版指标用 **干旱指数**（已有公式、已有点色）。气温/降水面作为同一套格点换输入，答辩有余力再加下拉。

## 三、算法（必须写进纯函数，不要堆进 Vue）

### 3.1 为什么用 IDW

演示站点数个，不适合上克里金 / 高斯过程。反距离加权（IDW）公式短、可讲、CPU 可算：

```text
某个格点的值 = Σ (wi × 第 i 站的值) / Σ wi
wi = 1 / (距离 ^ p)，p = 2
距离过近（< 1e-6 度）直接用该站值，避免除零
```

距离用经纬度差的平面近似即可（演示范围小，不引入 turf）。

### 3.2 格网

- 只对 **当前 `MonitorRegionId` 可见站点** 求 `min/max lat/lng`，再向外扩约 0.15°，得到 bounds。  
- 格网 **40 × 40**（1600 点）。再密在 CPU 上无必要。  
- 某格点到最近站超过 **1.2°**（约 100 km 量级）则透明，避免东北站把颜色抹到渤海。  
- 站点 &lt; 2 个：不画面，只保留圆点（插值没有几何意义）。

### 3.3 上色

复用圆点逻辑，便于口播「点和面是同一套指数」：

| 干旱指数 | 颜色 | 与圆点 |
|----------|------|--------|
| ≥ 70 | `#cf1322` | 同 `useMonitorMarkers` |
| ≥ 40 | `#d46b08` | 同 |
| &lt; 40 | 现网 status 绿/蓝系，或固定 `#389e0d` 半透明 | 面层用固定绿，避免和预警红抢 |

Canvas `globalAlpha` 约 0.45，底图路网仍能看见。

气温面（二期）：蓝 → 白 → 红，按 15–40℃ 线性拉。降水面：白 → 蓝。都走同一 `idwGrid`，只换 `value` 和色标。

### 3.4 输入从哪读

不要新 API。

```ts
interface IdwStation {
  lat: number
  lng: number
  value: number   // 首版 = droughtIndex(soilMoisture, dryDays)
  online?: boolean
}
```

`MapVisualization` 里已有筛选后的监测点；`value` 在组合函数里算，与 marker 同一公式。`weatherReadings` / `sensorReadings` 不必为插值再拉一遍。

## 四、页面怎么接

只改 **实时监测**（`MapVisualization.vue`），相关数据遥感 Tab **不要**再叠一张气象面（和 NDVI 抢图层）。

控件放在现有区域切换附近：

- 开关：插值面开/关（默认关，避免首屏花）  
- 可选二期：`干旱指数 | 气温 | 降水`  

实现要点：

1. `watch` 点位数组 + 开关 → 调 `buildIdwDataUrl(stations, bounds, 40)` 得到 PNG data URL。  
2. `L.imageOverlay(url, bounds, { opacity: 0.45, interactive: false })`，**垫在 marker 下面**（pane 或 `bringToBack`）。  
3. 区域从京津冀切到东北：拆掉旧 overlay，用新 bounds 重算。  
4. 不引入 `leaflet.heat`：那是点密度，不是「有数值的插值面」。

## 六、验收

- [ ] 京津冀至少河间 + 雄县 + 栾城在线时，打开开关能看到三站之间的色斑，不是三颗孤立点。  
- [ ] 关掉开关，地图回到只有圆点。  
- [ ] 把某站 `online: false`，该站不参与插值（可用单测喂点）。  
- [ ] 切到东北四省后，面跟着东北站走，不会把河间颜色拉过去。  
- [ ] 图例或角标说明「站点插值，非卫星」。  
- [ ] 规则链预警条数不因打开图层而变化。

## 七、明确不做

- 不上克里金、不上真实和风格点产品。  
- 不把 NDVI/墒情 WebP 改成「算出来的」；那些仍是遥感资产。  
- 不在相关数据气象 Tab 再画一张全国热力图。  
- 不把插值结果写入 `alerts`（面只展示，预警仍走链 1/2/3）。  
- 不为插值加 Python 服务。
