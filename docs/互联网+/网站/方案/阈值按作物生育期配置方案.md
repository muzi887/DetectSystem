# 阈值按作物 / 生育期配置方案

> 补齐 [`2.0非AI模块实现方案.md`](./2.0非AI模块实现方案.md) 验收项「`thresholdProfiles` 可按作物/生育期配置」。  
> **状态**：✅ 已按方案 B 落地（2026-08-22）。  
> **不改** Flask、P3、链 1 耐受公式、PUT 路径。  
> **做法**：仍是 **一站一行**；气象 Tab 增加作物、生育期；切换组合可套用推荐四档。

---

## 一、缺口（现在卡在哪）

原方案想：小麦拔节期和水稻灌浆期，黄线/红线可以不一样，表单里能选作物和生育期。

现在：

- 气象 Tab 只能改四个数：墒情提示/告警、气温提示/告警
- `ThresholdProfile` **没有** `crop`、`growthStage`
- `thresholdProfiles` 在 `db.json` 里是 `[]`，没保存过的站走默认 25/15、32/38
- 链 3 要作物时写死 `小麦`、生育期写死 `拔节`（`persistRules.runChain3OnDb`）

所以农技员**不能**表达「这座站现在种玉米、抽雄期」；链 3 的「适温 + 小麦」因子也和页面无关。

---

## 二、三种做法（选推荐）

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| A. 一站多行，按作物×生育期各存一套 | `pointId + crop + growthStage` 复合键 | 最贴近 7 月 JSON | 要改 GET/PUT、链 1 选哪一行、空库行为全变 | 竞赛不划算 |
| **B. 一站一行 + 作物/生育期字段 + 推荐预设** | 现有 `pointId` 主键；多两个下拉；切换组合时可用预设填四档数字（可再手改） | 改动面小；链 3 能读到真作物；答辩能演示「换作物数字跟着变」 | 一站不能同时存两套作物（演示一站一种作物即可） | **采用** |
| C. 只加下拉、数字永远手填 | 有作物标签但阈值不联动 | 更少代码 | 答辩看不出「按生育期配置」 | 不采用 |

**B 的产品行为：**

1. 打开某监测站 → 读该站一行（没有则默认：小麦 / 拔节 / 25·15·32·38）。
2. 改「作物」或「生育期」→ 弹出或直接套用该组合的**推荐四档**（已手改过的可确认覆盖）。
3. 点保存 → PUT 整行（含作物、生育期、四档数字、耐受分钟仍用默认 30/10，本阶段表单可不露出耐受）。
4. 链 1 仍只看四档数字 + 耐受（与现在相同）。
5. 链 3 用保存的 `crop` / `growthStage`，不再写死小麦拔节。

## 三、数据与预设

### 3.1 类型（在现有扁平字段上加两列）

[`src/types/rules.ts`](../../../../src/types/rules.ts) 的 `ThresholdProfile` 增加：

```ts
crop: string        // 中文：小麦 | 玉米 | 水稻
growthStage: string // 中文：拔节 | 抽穗 | 灌浆 | 成熟
```

链 3 用 `crop.includes('小麦')`，**必须存中文「小麦」**，不要存 `wheat`（7 月原文英文 id 在本方案不用，以免链 3 失效）。

`DEFAULT_THRESHOLD_PROFILE` 补上 `crop: '小麦'`、`growthStage: '拔节'`。

PUT 仍按 `pointId` 覆盖整行；body 带上这两字段。`profileForPoint` 找不到行时返回带默认作物的默认档。

### 3.2 推荐预设表（纯函数，可单测）

新建 `src/utils/thresholdPresets.ts`：

```ts
export type CropOption = '小麦' | '玉米' | '水稻'
export type StageOption = '拔节' | '抽穗' | '灌浆' | '成熟'

export function presetFor(crop: CropOption, stage: StageOption): Pick<
  ThresholdProfile,
  'waterStressHint' | 'waterStressAlert' | 'heatHint' | 'heatAlert'
>
```

演示用数字（与现网默认对齐，只在组合上做可讲清的差异）：

| 作物 | 生育期 | 墒情提示 | 墒情告警 | 气温提示 | 气温告警 | 答辩怎么讲 |
|------|--------|----------|----------|----------|----------|------------|
| 小麦 | 拔节 | 25 | 15 | 32 | 38 | **现网默认**，京津冀演示主档 |
| 小麦 | 灌浆 | 28 | 18 | 30 | 36 | 灌浆更怕干、更怕热 |
| 玉米 | 抽穗 | 22 | 14 | 34 | 40 | 玉米耐旱耐热略高 |
| 玉米 | 成熟 | 20 | 12 | 34 | 40 | 后期可稍干 |
| 水稻 | 拔节 | 35 | 25 | 32 | 38 | 水稻要水，提示线明显高于小麦 |
| 水稻 | 灌浆 | 40 | 30 | 32 | 38 | 灌浆期更不能断水 |

未列出的组合（如小麦+抽穗）：**回退到该作物「拔节」行，没有则小麦拔节默认**。

耐受分钟本阶段全部保持 hint 30 / alert 10 / 涝渍 80，不进表单。

### 3.3 种子

`db.json` 的 `thresholdProfiles` 不要长期空着，至少：

- 河间 `pointId: 1`：小麦 / 拔节 / 默认四档（明示「已配置」）
- 雄县 `pointId: 2`：小麦 / 拔节 / 默认四档（低墒演示仍走链 1，**不要**把雄县改成水稻高阈值，否则干旱预警会停）

改完跑 `pnpm run sync:mock-db`（`thresholdProfiles` 已在 `syncKeys`）。

## 四、页面

仍在相关数据 **气象 Tab** 右侧「阈值配置」，不要新页面。

在四档数字 **上方** 加两列下拉（与现有 `threshold-grid` 同一套玻璃样式）：

- 作物：小麦 / 玉米 / 水稻
- 生育期：拔节 / 抽穗 / 灌浆 / 成熟

交互：

1. 切监测站 → 已有 `loadThresholds`，把 `crop`/`growthStage` `Object.assign` 进 `thresholdForm`。
2. 改下拉 → 调用 `presetFor` 填四档；若四档已被用户改过且与当前预设不同，用 `Modal.confirm`「是否套用该作物生育期的推荐阈值？」；选否只改标签、不动数字。
3. 保存仍 `savePointThresholds`，body 带 `crop`、`growthStage`。

相关数据已要求农技员角色，不必做合作社 403。

---

## 五、规则链怎么用这两列

| 链 | 用法 |
|----|------|
| 链 1 | **只读数字**。作物不改变耐受逻辑。换水稻预设后，同一墒情可能不再告警——这是预期。 |
| 链 2 | 不读剖面。 |
| 链 3 | `crop: profile.crop \|\| '小麦'`，`growthStage: profile.growthStage \|\| '拔节'`。把 `persistRules` 里的断言类型改成正式字段。水稻站不会命中「小麦适温」因子——这是预期。 |

不改 `evaluatePestRisk` 的凑分公式，只改输入从哪来。

CJS `ruleChainRunner.cjs` 的 `profileForPoint` / 默认对象同样补两字段，避免宝塔 Mock 链 3 仍当小麦。
