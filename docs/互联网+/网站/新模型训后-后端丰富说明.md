## 二、23 类清单（与模型对齐）

实施时用 `pest-cls-meta.json` 的 `classes` 做最终核对。下列为训练手册约定标签，**键名必须与模型输出完全一致**：

| 作物 | `cropType` | 类别 |
|------|------------|------|
| 共用 | 任意 | 健康 |
| 小麦 | `wheat` | 小麦锈病、小麦赤霉病、小麦白粉病、小麦蚜虫为害 |
| 玉米 | `corn` | 玉米大斑病、玉米锈病、玉米南方锈病、玉米小斑病、玉米弯孢叶斑病、玉米褐斑病、玉米瘤黑粉病、玉米茎腐病、玉米穗腐病 |
| 番茄 | `tomato` | 番茄早疫病 |
| 水稻 | `rice` | 水稻白叶枯病、水稻褐斑病、水稻负泥虫为害、稻瘟病、水稻叶鞘腐败病、水稻叶黑粉病、水稻窄条斑病、稻颈瘟 |

作物约束规则：用户选择某作物时，只在 **该类作物相关病名 ∪ {健康}** 上对 softmax 置零后再归一化。`cropType` 未知或不在表中时 **不过滤**。

## 四、推理服务层（`ml-bjj/serving`）待落地

### 4.1 响应信息加厚

在现有 `result` / `confidence` / `level` 之外增加：

| 字段 | 作用 |
|------|------|
| `topk`（top3） | `[{ "label", "confidence" }, …]`，便于复核与答辩展示易混淆类 |
| `model_version` | 来自 `pest-cls-meta.json` 的 `trained_at` / `best_val_acc` / 类数 |
| `treatment` | 服务端附带该类知识库片段；无条目时给降级对象，不省略字段 |
| `needs_review` | `confidence < 0.7` **或** top1 与 top2 分差 `< 0.10` 为 `true` |
| `details.isReliable` | 与现网兼容：`not needs_review` |
| `details.engine` | 由 `"v3"` 改为 `"bjj-23"` |

### 4.2 按作物约束推理

见 §二。实现为纯函数（便于单测），再由 `PestClassifier.predict` 调用。Mock 推理（`ML_BJJ_USE_MOCK=1`）也必须遵守同一作物集合。

### 4.3 批量、历史、反馈（P2，本规格保留接口形状）

| 接口 | 说明 |
|------|------|
| `POST /api/analysis/batch` | 一次多图，返回列表 |
| `GET /api/analysis/history` | 识别记录（时间、病名、置信度、地块 id） |
| `POST /api/analysis/feedback` | 用户纠正标签 → 写入 `ml-bjj/data/hard_cases/pending/` |

P0/P1 **不实现** batch / history / feedback；P2 计划另开。

### 4.4 工程化

- 启动时校验权重内 `classes` 长度与 meta 一致；不一致则拒绝启动并打日志  
- `/health` 返回：`classes_count`、`classes`、`weights_mtime`、`cuda`、`model_version`、`mock`  
- 请求：上传大小上限保持现有校验；不在本轮上 gunicorn / ONNX / 鉴权
