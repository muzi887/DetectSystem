# 什么是规则链

> 先讲清「规则链」这个词，再说明本仓库里 P3 与 2.0 两套规则链是什么关系。  
> 三条链的阈值、API、任务步骤见方案与实施计划，本文不重复。

---

## 一、规则链是什么

**规则链**是一串人事先写好的「如果……就……」。数据进来后按这些条件匹配，得到预警、级别或建议。它 **不是** 神经网络，也 **不是** 区块链、链表。

「链」只表示处理顺序：输入 → 套规则 → 有时先记状态（例如超标要持续多久）→ 产出 → 页面去用。可以分成几条并行的岗，不必真的首尾焊成一条。


|         | 规则链              | 本项目识病 AI  |
| ------- | ---------------- | --------- |
| 知识从哪来   | 人把阈值、条件写进代码或配置   | 从大量叶片图里学  |
| 典型判断    | 墒情过低且持续够久 → 干旱预警 | 这张叶子像稻瘟病  |
| 能不能讲清依据 | 能指出命中了哪一条        | 主要给病名和置信度 |


生活类比：仓库消防不是烟感一响就喷水，还要看是否持续、要不要联动喷淋、要不要通知值班。每一环都是规则，串起来就是规则链。

本系统用规则链处理 **气象、墒情、预报和地块风险** 这类「条件说得清」的问题；叶片认病仍走 PyTorch。

## 二、本仓库里这个词出现了两次

同一套「用 if 做判断」的思想，用在两个地方，**不是同一条链的前后两步**。


|             | P3（训后 Flask）                                                 | 2.0 总线（Mock）                                   |
| ----------- | ------------------------------------------------------------ | ---------------------------------------------- |
| 计划文件        | `[新模型训后-P3-规则链与工程化实施计划.md](../实施计划/新模型训后-P3-规则链与工程化实施计划.md)` | `[规则链-2.0总线实施计划.md](../实施计划/规则链-2.0总线实施计划.md)` |
| 方案来源        | 训后规格里的「病名 × 气象/墒情」                                           | `[规则链建模与实现方案.md](../方案/规则链建模与实现方案.md)`         |
| 干什么         | 用户 **刚看完一张叶子**，用当前温湿墒决定要不要抬高 **这一次识别** 的级别                   | 地块 **自己值班**：现在干不干、未来会不会极端天气、虫情风险够不够分           |
| 跑在哪         | Flask :5000，`disease_env_rules.py`                           | Mock :3000，定时调度 + `src/utils` 规则               |
| 输入          | **病名** + 此刻气温 / 湿度 / 墒情                                      | 传感、7 日预报、NDVI 等（链 3 可统计近期 AI 次数）               |
| 输出          | 分析 JSON 的 `level`、`env_context`                              | `alerts`：`[自动预警]` / `[极端天气]` / `[虫情风险]`        |
| 耐受 / 60 秒闹钟 | 没有；一次请求算完                                                    | 链 1 有耐受；总线约每 60 秒跑一轮                           |


日常说「规则链」而不加前缀时，多半指 **2.0 那三条 + 调度**。P3 文件标题里的「规则链」是识病接口上的一小段同类逻辑。

## 三、P3 和 2.0 的关系

**平行，不是包含。** P3 不是把 2.0 链 1 搬进 Flask。链 1 要「超标持续满若干分钟才写 `[自动预警]`」。P3 没有计时：这次请求里湿度高、病是稻瘟，就把这次的 `level` 提到 high。

**数字可以共用，产出不能混。** 墒情 15%、气温 38℃ 与方案链 1 相同。P3 用它们改 **这一次识病**；2.0 用它们判断 **地块要不要自动报警**。智慧决策读的是预警文案前缀，不是 Flask 的 `env_context`。

**现有** `evaluateDisasterRules` **谁也不等于。** 它仍是当场比阈值、返回 JSON、不写 `alerts`。P3 与它平行（再乘上病名）；2.0 才把三条链和调度真正落地。两份计划都约定：不把它当成已经完成的总线。

2.0 实施计划写明 **不改 Flask、不替代 P3**。P3 写明 **不实施** 尚未编码的 `[自动预警]` 环境链。可以先做完识病叠环境，再做 Mock 值班预警，互不接管。

```text
智能分析上传
    → P3：病名 × 当前环境 → 这次结果的 level / advice
    → 前端可用该 level 去建 [AI识别] 预警

Mock 定时（2.0 落地后）
    → 链1 耐受 → [自动预警]
    → 链2 预报 → [极端天气]
    → 链3 凑分 → [虫情风险] 草稿
    → 预警中心 / 智慧决策读 alerts
```

三个词只属于 2.0（不要安到 P3 上）：

- **耐受计时**：链 1，超标要持续够久才报警。  
- **预报**：链 2 看未来 7 天，无耐受。  
- **虫情加权**：链 3 多条迹象各 +1 分再分级。

## 五、小结


| 说法        | 含义                            |
| --------- | ----------------------------- |
| 规则链（概念）   | 用写死的条件从监测数据推出预警或建议            |
| 本项目常说的规则链 | 2.0：三条链 + 定时写 `alerts`，服务智慧决策 |
| P3 的规则链   | 看图之后叠当前环境，只改这一次识别结果           |
| 二者关系      | 平行；共用部分阈值；不互相替代               |
