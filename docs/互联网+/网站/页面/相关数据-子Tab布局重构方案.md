## 一、现状：空间是怎么被吃掉的

桌面布局（[`RelatedData.vue`](../../../../src/views/user/RelatedData.vue) `.data-page-content`）：

```text
┌ AppLayout 顶栏：首页 | 相关数据 | 灾害实时监测 | … ─────────────┐
┌ data-page-content（max-width: 1280px，padding 30，gap 30）───┐
│ ┌ 主玻璃卡 chart-panel ─────────────┐  ┌ nav-buttons 220px ─┐ │
│ │ 标题 + 简报 / 详情                 │  │ 传感器数据 (地)     │ │
│ │ 地图 / 折线 / 气象 3×3              │  │ 无人机遥感 (空)     │ │
│ │ AI 智能分析条                      │  │ 气象数据 (天)       │ │
│ └────────────────────────────────────┘  │ GIS 数据 (图)       │ │
│                                          │ （下方大片空白）     │ │
└──────────────────────────────────────────┴────────────────────┘
```

| 项 | 现状 |
|----|------|
| 内容区上限 | `--page-max-width: 1280px` |
| 左右内边距 | `30px × 2` |
| 主卡与右栏间隙 | `30px` |
| 右栏固定宽 | **220px** |
| 右栏按钮 | 高 **60px**、间距 20px，文案短、按钮大 |
| 窄屏 ≤992px | 已改成主卡在上、Tab **横排在下**（2×2 换行） |

粗算桌面主卡可用宽：

```text
1280 − 60（页边）− 30（间隙）− 220（右栏）≈ 970px
主卡再扣 glass 内边距 24×2 → 地图/表格约 922px
```

收回右栏后主卡约 **1220px** 内容宽（再扣内边距约 **1172px**）。**一次性多出约 250px（地图区大约宽 27%）**。

右栏四个按钮加间距大约只要 **300px 高**，栏却拉满整列，下面空一大块——**占的是整列宽度，用的只是一截高度**。

## 二、拥挤是不是右栏造成的

**主要是。** 右栏把本页唯一的大玻璃卡向左挤，地图、气象左右栏、标题行按钮都在变窄的卡里抢位。

主卡内部也有挤（本方案 **不一起改逻辑**，只吃「变宽」的红利）：

| 位置 | 挤在哪 | 和右栏的关系 |
|------|--------|----------------|
| 标题行 | 监测站选择 + 生成简报 + 查看详情已同一行 | 卡变宽后这一行更松 |
| GIS / 无人机地图 | 缩放、图注、图例叠在图上 | 图面变宽，叠字相对不那么堵 |
| 气象 Tab | 左 3×3 实时 + 右预报/阈值 | 已按「左实时右预报」定稿；变宽后右表更好读 |
| 底栏 AI 条 | 一句长结论文案 | 变宽后少折行 |

所以：**先把四 Tab 挪走，比先改地图叠层或气象网格更划算。**

---

## 三、要不要「设在导航栏下方一行」

**要横排，但不要塞进 `AppLayout` 顶栏。**

顶栏已经是：品牌 + **站点一级导航** + 区域选择 + 搜索 + 账号。地 / 空 / 天 / 图只在 `/related-data` 有意义。写进顶栏会：

- 和「相关数据」一级入口重复（一个进页，一个切子页）
- 其它页面顶栏高度/内容不一致
- 动 [`AppLayout.vue`](../../../../src/layouts/AppLayout.vue)，和本页数据逻辑无关

正确位置是：**视觉上紧贴顶栏下方，但 DOM 仍在本页里**——本页第一行就是四 Tab，第二行才是全宽主卡。用户说的「导航栏下方一行」按这个理解即可。

## 四、方案选型

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| A. 右栏变窄 | 220px → 约 160px，或改图标列 | 改动小 | 空高还在；主卡只多几十像素 | 不采用 |
| **B. 页内次级 Tab 横条** | 顶栏下、主卡上，四等分一行 | 主卡拿回 ~250px；空高消失；窄屏也是「先 Tab 后内容」 | 多占约 44px 高度 | **★ 推荐** |
| C. 塞进主卡标题行 | 和简报/详情同一行 | 不再单独占行 | 标题行刚排过三个操作，再塞四个 Tab 必折行 | 不采用 |
| D. 写进 AppLayout | 相关数据路由时顶栏下加第二导航 | 「真」在导航下方 | 布局耦合、其它页不一致 | 不采用 |
| E. 维持右栏 | 只美化按钮 | 零风险 | 拥挤和空白都不解 | 不采用 |

窄屏（`width <= 992px`）：与 B 一致——**先 Tab 后主卡**；可由一行改为两行（2×2），不要再把 Tab 垫在地图下面（现在 `order` 就是主卡 0、Tab 1，要改掉）。

## 五、定稿结构（方案 B）

```text
┌ AppLayout 顶栏（站点导航，不改）─────────────────────────────┐
┌ data-page-content 改为纵向：Tab 条 + 全宽主卡 ───────────────┐
│ ┌ 子 Tab 一行（传感器·地 | 无人机·空 | 气象·天 | GIS·图）──┐ │
│ └──────────────────────────────────────────────────────────┘ │
│ ┌ 主玻璃卡（flex:1，占满剩余宽高）─────────────────────────┐ │
│ │ 标题 + 监测站选择 / 生成简报 / 查看详情                   │ │
│ │ 地图 / 折线 / 气象网格                                     │ │
│ │ [AI 智能分析]                                              │ │
│ └──────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

### 5.1 交互（与现在相同）

- 仍是四个本地 `currentTab`：`sensor` / `drone` / `weather` / `gis`
- `switchTab`、遥感 `invalidate`、气象/传感器拉数 **不改接口**
- 当前项：深绿底 + 浅绿描边（沿用 `.active-btn`），不要 Ant 默认蓝
- 键盘：保持点击切换即可；不必做成路由子路径（`/related-data?tab=` 可以后再加，本方案不做）

### 5.2 文案

按钮现文案偏长（「传感器数据 (地)」）。横排四等分放得下，**先保留全文案**，避免和说明书不一致。若仍显挤，第二步再改成「地 · 传感器」这种短标签（须同步使用说明书，本方案第一刀不做）。

### 5.3 布局 CSS 要点（实施时）

```css
.data-page-content {
  display: flex;
  flex-direction: column;   /* 现在是横向 */
  height: 100%;
  gap: 16px;                /* 现在 30；Tab 与主卡贴近顶栏 */
}

.nav-buttons {
  width: 100%;
  flex-direction: row;
  flex-shrink: 0;
  gap: 8px;
}

.nav-btn {
  flex: 1;
  height: 40px;             /* 现在 60px */
}

.chart-panel {
  flex: 1;
  min-width: 0;
  min-height: 0;
}
```

DOM 顺序改为：**先 `.nav-buttons`，后 `.chart-panel`**（和视觉、窄屏一致）。不要用 `order` 把 Tab 藏到下面。

### 5.4 明确不改

- Flask / Mock / `ndviLayers` / `moistureLayers` / 气象与传感器接口
- 「查看详情」抽屉、生成简报
- 气象 Tab 内部「左实时 / 右预报+阈值」（已定稿）
- 站点顶栏菜单结构
