## 一、先分清：三个 Tab 不全是「贴图」

| Tab | 页面上的名字 | 现在展示什么 | 组员「图」怎么接 |
|------|----------------|--------------|------------------|
| `sensor` 地 | 地面监测站 | ECharts 气温/墒情折线；按钮切气象九宫格+预报+阈值 | **不是贴图**。换哪一天的数，改 `sensorReadings` / `weatherReadings`。已画好的海报见 §七 |

## 二、无人机（空）：当前选哪张图

三层：

```text
db.json 写「用哪张图、盖在哪块地、哪一天」
        ↓  GET /ndviLayers
Pinia remoteSensing：按你选的地块/日期挑一行
        ↓  imageAsset → Vite 打包 URL
RemoteSensingMap：Leaflet imageOverlay 铺在 bounds 上
```

页面打开时 `remoteStore.fetchAll()`。Mock 失败则用 `NDVI_DEMO_LAYER`。

控件在 [`NdviLayerControls.vue`](../../../../src/components/remote-sensing/NdviLayerControls.vue)：

1. **地块** `selectedFieldId`（`hejian` / `xiongxian` / `luancheng`）
2. **影像日期**：只列出当前地块在 `ndviLayers` 里出现过的 `date`，默认最新一天
3. 可选 **对比历史**：同一地块另一天，透明度滑杆

选图（[`remoteSensing.ts`](../../../../src/stores/remoteSensing.ts)）：先按 `fieldId` 过滤，再按日期；`toRasterView` 用 `resolveImageAsset(imageAsset)`。

[`RelatedData.vue`](../../../../src/views/user/RelatedData.vue) 仅在无人机 Tab 把 `currentNdviRaster` 传给地图（`mode=ndvi`）。红框、航迹只在 NDVI 模式画。

### 2.1 `imageAsset` 怎样变成真正的图片

[`remoteSensingLayers.ts`](../../../../src/constants/remoteSensingLayers.ts)：**名字 → import 后的 URL**。

| `imageAsset` | 实际文件 |
|----------------|----------|
| `ndvi-heatmap` | `src/assets/ndvi-heatmap.webp` |
| `ndvi-heatmap-may20` | `src/assets/ndvi-heatmap-may20.webp` |
| `soil-moisture-heatmap` | `src/assets/soil-moisture-heatmap.webp`（卫星页已不用作主图） |

`resolveImageAsset`：未登记的名字会静默落到默认 NDVI。**必须 `import` 登记**，Vite 不会按 JSON 字符串扫文件夹。

### 2.2 现在库里实际有几张「不同的图」

`ndviLayers` 四行、文件其实 **两张**：河间 5/1 与 5/20 能看出两期；雄县/栾城仍共用 `ndvi-heatmap`，换地块只是框挪了。组员按天出的新图，就是为了打破「多地共用一张」。

## 三、卫星（天）：出图 JPG，不是 Leaflet

成品图在 `docs/出图/`（干旱 / 高温 / 暴雨 / 大风 / 总）。竖版 JPG 自带标题和图例，**不要**当 `imageOverlay`。

```text
scripts/build-satellite-catalog.ts  扫描出图目录
        ↓
public/satellite/catalog.json     类型 → 日期 → /satellite-maps/... URL
        ↓
RelatedData 右栏选类型/日期，左栏 <img>
vite.config.ts  开发时 /satellite-maps/ → docs/出图/
```

出图合计约 900MB，**不要拷进 `public/`**。改文件后重新跑：

```bash
pnpm exec tsx scripts/build-satellite-catalog.ts
```

文件名（年份 2025）：`1.5.jpg` → `2025-01-05`；`高温7.08.jpg`；`2025-06-03 高温.jpg`；`xindafeng.jpg` 为汇总；`mmexport*` 忽略。

页面文案是「大风专题 65 期 · 最新日期」，不是「共 65 天有图」。

## 四、请组员按这个交图

### 4.1 无人机 NDVI（空）

每个「地块 × 日期」一张。`.webp` 优先，单张建议 &lt; 2 MB。命名：

```text
ndvi-{地块英文id}-{YYYYMMDD}.webp
例：ndvi-hejian-20260520.webp
```

地块 id 必须是现有 `fields.id`。另附表：文件名、地块、日期、来源。`bounds` 默认抄该地块 `fields` 框。同一地块至少两天才能「对比历史」。

### 4.2 卫星专题（天）

按灾害放到 `docs/出图/{干旱|高温|暴雨|大风}/`，文件名能解析出月日。汇总放 `docs/出图/总/`（`xinganhan` 等）。交图后重建 `catalog.json` 并确认开发服务已映射 `/satellite-maps/`。

### 4.3 地面监测站（地）

说明交的是 **A. 数字表** → `sensorReadings` / `weatherReadings`（推荐），还是 **B. 已画好的海报** → 现成 Tab 不会显示，见 §七。

## 五、把 NDVI 接到网站（空）

每增加一种新画面：**放文件 → 登记名字 → 写一行图层**。

1. 复制到 `src/assets/`（与现有 webp 同级）。  
2. 在 `remoteSensingLayers.ts` 里 `import` 并写入 `REMOTE_SENSING_ASSETS`。左边字符串 = JSON 的 `imageAsset`。  
3. 在 `src/mock/db.json` 的 `ndviLayers` 增行（`id` 不重复；`bounds` 与 `fields` 一致）。  
4. `pnpm run sync:mock-db`。  
5. `pnpm mock` + `pnpm dev` → 相关数据 → 无人机遥感 → 换地块、换影像日期。

## 七、地若组员交的是「图」而不是表

| 做法 | 适用 | 工作量 |
|------|------|--------|
| 数字填进 `sensorReadings` / `weatherForecast` | 与折线、预报一致 | 小，**推荐** |
| 弹窗 `<img>` 或简报附图 | 答辩展示制图成果 | 新 UI 或走现有简报附图 |
| 硬接到 NDVI / 卫星出图目录 | 和地块、专题图搅在一起 | **不推荐** |

不要把气象海报的 `imageAsset` 写进 `ndviLayers`。

---

## 八、容易踩的坑

1. 只改 json、不改 `REMOTE_SENSING_ASSETS` → 新名字落到默认 NDVI。  
2. 雄县/栾城仍写 `ndvi-heatmap` → 和河间同一张图。  
3. 日期必须 `YYYY-MM-DD`。  
4. NDVI 对比两期 `bounds` 应相同。  
5. 忘了 `sync:mock-db`。  
6. 图片过大 → 先压 webp。  
7. 卫星出图只丢进 `docs/出图/` 却不重建 catalog → 下拉没有新日期。  
8. 把出图 JPG `import` 进打包 → 体积爆炸。
