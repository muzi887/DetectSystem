# 相关数据页 · 每日图怎么显示、组员图怎么接入

> 页面：`/related-data` · [`RelatedData.vue`](../../../../src/views/user/RelatedData.vue)  
> **给谁看**：你自己接线；也给做图的同学当交图清单。  
> **基准**：2026-08-22 代码。

---

## 一、先分清：四个 Tab 并不都是「贴图」

相关数据底下四个按钮是 **地 / 空 / 天 / 图**。现在只有 **空、图** 会把组员做的栅格图铺到 Leaflet 地图上。地、天是数字和折线，**没有**走 `imageAsset` 这套管线。

| Tab | 页面上的名字 | 现在展示什么 | 组员「每一天的图」怎么接 |
|------|----------------|--------------|--------------------------|
| `sensor` 地 | 传感器数据 | ECharts：**气温 / 墒情** 历史折线（可多站） | **不是贴图**。要换「哪一天的数」，改 `db.json` 的 `sensorReadings`（一天一行），不是丢 jpg。若组员画的是曲线截图，见 §六 |
| `drone` 空 | 无人机遥感 | 卫星底图 + **NDVI 热力贴图**；可选对比期、红框、航迹 | **主接入口**。按地块 + 日期各一张图 |
| `weather` 天 | 气象数据 | 实时 9 张卡片 + 7 日预报表 + 阈值 | **不是贴图**。数来自 `weatherReadings` / `weatherForecast`。若组员做了天气图，见 §六 |
| `gis` 图 | GIS 数据 | 卫星底图 + **墒情热力贴图**；可点图查最近站 | **第二接入口**。按日期一张区域图（目前**不按地块**） |

组员若按「四个部分各出一套每日图」准备，**空、图**按本文 §四、§五接入即可；**地、天**不要硬塞进 NDVI 目录，否则接不上现有控件。

## 二、空 / 图：当前选哪张图（逻辑）

可以想成三层：

```text
db.json 里写「用哪张图、盖在哪块地、哪一天」
        ↓  GET /ndviLayers  或  GET /moistureLayers
Pinia remoteSensing：按你选的地块/日期挑一行
        ↓  imageAsset 字符串 → 真实文件 URL
RemoteSensingMap：Leaflet imageOverlay 把图铺在 bounds 上
```

页面打开时 `remoteStore.fetchAll()` 一次拉 `fields`、`ndviLayers`、`moistureLayers`。Mock 失败则用写死的兜底图（`NDVI_DEMO_LAYER` / `MOISTURE_DEMO_LAYER`），看起来像「永远那一张」。

### 2.1 无人机 Tab（NDVI）

控件在 [`NdviLayerControls.vue`](../../../../src/components/remote-sensing/NdviLayerControls.vue)：

1. **地块** `selectedFieldId`（如 `hejian` / `xiongxian` / `luancheng`）
2. **影像日期** `selectedNdviDate`：只列出 **当前地块** 在 `ndviLayers` 里出现过的 `date`，默认 **最新一天**
3. 可选 **对比历史**：同一地块另一天，两张图叠在**同一块** `bounds` 上，用透明度滑杆

选图代码（[`remoteSensing.ts`](../../../../src/stores/remoteSensing.ts)）：

- 先 `ndviLayers.filter(fieldId === 当前地块)`
- 再 `find(date === 当前日期)`，找不到就用该地块第一行
- `toRasterView`：`imageUrl = resolveImageAsset(imageAsset)`，带上该行的 `bounds` / `date` / `source`

[`RelatedData.vue`](../../../../src/views/user/RelatedData.vue) 把 `currentNdviRaster` 传给地图：

```text
mode=ndvi
image-url = 当期图
bounds    = 当期行的 bounds（应与地块框一致）
compare-image-url = 打开对比时才有
```

GIS 墒情模式 **不**走地块下拉；红框、航迹也只在 NDVI 模式画。

### 2.2 GIS Tab（墒情）

- 表是 `moistureLayers`，**没有** `fieldId`，一张图代表整片演示区。
- `selectedMoistureDate` 默认最新一天，但页面 **没有日期下拉**，只在图注里显示日期。现在库里只有 **1 行**（`2026-05-20`），所以切 Tab 永远那一张。
- 点地图查墒情是找最近监测点的数字，**不是**读热力图像素颜色。

### 2.3 `imageAsset` 怎样变成真正的图片

[`remoteSensingLayers.ts`](../../../../src/constants/remoteSensingLayers.ts) 里是一张 **名字 → Vite 打包后的 URL** 表：

| `imageAsset`（写在 db.json） | 实际文件 |
|------------------------------|----------|
| `ndvi-heatmap` | `src/assets/ndvi-heatmap.webp` |
| `ndvi-heatmap-may20` | `src/assets/ndvi-heatmap-may20.webp` |
| `soil-moisture-heatmap` | `src/assets/soil-moisture-heatmap.webp` |

`resolveImageAsset`：名字在表里就用它；名字带 `moisture`/`soil` 却未登记 → 墒情兜底图；其它未登记 → **一律河间那张 NDVI**。所以只把 jpg 丢进 `src/assets/`、JSON 里写了新名字、**却忘了改这个表**，页面会静默显示旧 NDVI。

**必须用 `import` 登记。** Vite 不会按 JSON 字符串去扫文件夹。

### 2.4 现在库里实际有几张「不同的图」

`ndviLayers` 四行、文件其实 **两张**：

| id | 地块 | 日期 | 用的图 |
|----|------|------|--------|
| 1 | 河间 | 2026-05-20 | `ndvi-heatmap-may20`（另一张） |
| 2 | 河间 | 2026-05-01 | `ndvi-heatmap` |
| 3 | 雄县 | 2026-05-20 | **同一张** `ndvi-heatmap`（只是 bounds 换成雄县） |
| 4 | 栾城 | 2026-05-20 | **还是** `ndvi-heatmap` |

所以：河间切 5/1 和 5/20 能看出两期；雄县/栾城换地块只是图被拉到另一块经纬度上，**画面内容相同**。组员按天出的新图，就是为了打破「多地共用一张」。

`moistureLayers` 仅 1 行，`soil-moisture-heatmap`，bounds 在栾城一带。

## 三、请组员按这个交图（清单）

### 3.1 无人机 NDVI（空）

每个「地块 × 日期」一张。建议：

- 格式：`.webp` 优先（现网如此），或 `.png` / `.jpg`（文件别太大，单张建议 &lt; 2 MB）
- 内容：已经上色的 NDVI 热力，透明或与田块对齐；**不要**指望网站再算 NDVI
- 命名（推荐，避免空格和中文）：

```text
ndvi-{地块英文id}-{YYYYMMDD}.webp
例：ndvi-hejian-20260520.webp
    ndvi-xiongxian-20260520.webp
    ndvi-luancheng-20260527.webp
```

地块 id 必须是现有 `fields.id`：`hejian` / `xiongxian` / `luancheng`。东北监测点目前 **没有** 对应 `fields` 行，没有地块就不要做 NDVI 下拉项，除非先加地块。

另外给一张表（Excel / 备注均可）：

| 文件名 | 地块 id | 日期 YYYY-MM-DD | 来源文案（如 DJI Mavic 3M） | 是否新拍/新出图 |
|--------|---------|-----------------|-----------------------------|-----------------|
| … | hejian | 2026-05-20 | DJI Mavic 3M | 是 |

`bounds` 默认 **抄该地块在 `fields` 里已有的框**，组员一般不用重测。除非图覆盖范围变了，再给 `[[南, 西], [北, 东]]`（纬度在前）。

对比功能：同一地块至少 **两天** 才开得了「对比历史」。

### 3.2 GIS 墒情（图）

按 **日期** 一张区域热力图（与 NDVI 不同，不跟单个田块走）：

```text
moisture-{YYYYMMDD}.webp
例：moisture-20260520.webp
    moisture-20260527.webp
```

注明日期、来源（如 Sentinel-2）。若覆盖范围仍是栾城演示框，bounds 可沿用现网 `[[37.88, 114.6], [37.92, 114.7]]`。

多天接入后，页面目前 **不会自动出现日期下拉**（见 §五），接线时要顺便加一个选择器，否则永远显示最新一天。

### 3.3 传感器 / 气象（地、天）

请组员说明交的是：

- **A. 数字表**（每天气温、墒情）→ 填进 `sensorReadings` / `weatherReadings`，网站自己画线；或  
- **B. 已经画好的折线/海报图** → 网站现成 Tab **不会显示**，不要放进 `ndviLayers`。若答辩必须贴图，见 §六。

## 四、你怎么把 NDVI 接到网站（空）

每增加一种新画面（新文件），做三件事：**放文件 → 登记名字 → 写一行图层**。只改 JSON 或只丢文件都不完整。

### 步骤 1：文件放到前端资源目录

复制到：

```text
src/assets/
```

（与现有 `ndvi-heatmap.webp` 同级。不要只放 `public/`，除非改解析逻辑。）

### 步骤 2：在代码里登记 `imageAsset`

改 [`src/constants/remoteSensingLayers.ts`](../../../../src/constants/remoteSensingLayers.ts)：

```ts
import ndviHejian20260520 from '@/assets/ndvi-hejian-20260520.webp'
import ndviXiongxian20260520 from '@/assets/ndvi-xiongxian-20260520.webp'
// …每种文件一行 import

export const REMOTE_SENSING_ASSETS: Record<string, string> = {
  'ndvi-heatmap': ndviHeatmap,
  'ndvi-heatmap-may20': ndviHeatmapMay20,
  'soil-moisture-heatmap': soilMoistureHeatmap,
  'ndvi-hejian-20260520': ndviHejian20260520,
  'ndvi-xiongxian-20260520': ndviXiongxian20260520
}
```

左边引号里的字符串 = JSON 里的 `imageAsset`，必须完全一致。

### 步骤 3：在 Mock 库增加或改写图层行

改 [`src/mock/db.json`](../../../../src/mock/db.json) 的 `ndviLayers`。`id` 不要重复。河间已有 5/1、5/20 时可改 `imageAsset` 指向新文件，或追加新日期：

```json
{
  "id": 5,
  "fieldId": "xiongxian",
  "date": "2026-05-27",
  "imageAsset": "ndvi-xiongxian-20260527",
  "bounds": [[38.94, 116.02], [38.99, 116.14]],
  "source": "DJI Mavic 3M",
  "ndviMin": 0.15,
  "ndviMax": 0.8
}
```

`ndviMin` / `ndviMax` 可选，链 3 虫情凑分会用来估该田 NDVI；没有则按代码默认中间值。新图若明显更绿/更黄，尽量填真实范围。

`bounds` 与对应 `fields` 行保持一致，否则贴图会漂到别的位置。

### 步骤 4：同步部署用的那份库

```powershell
pnpm run sync:mock-db
```

`ndviLayers` 已在 `syncKeys` 里。只改 `src/mock/db.json` 不同步，宝塔/线上 Mock 仍是旧图层。

### 步骤 5：本地看

`pnpm mock` + `pnpm dev` → 相关数据 → 无人机遥感 → 换地块、换「影像日期」。河间应能对比两期；雄县应看到 **雄县自己那张**，而不是河间图被拉伸。

## 五、你怎么把墒情图接到网站（图）

同样三步：文件 → `REMOTE_SENSING_ASSETS` → `moistureLayers` 新行，例如：

```json
{
  "id": 2,
  "date": "2026-05-27",
  "imageAsset": "moisture-20260527",
  "bounds": [[37.88, 114.6], [37.92, 114.7]],
  "source": "Sentinel-2"
}
```

然后 `pnpm run sync:mock-db`。

**缺的 UI：** GIS Tab 没有日期下拉。多天之后建议在 GIS 模式加一个与 NDVI「影像日期」同类的 `a-select`，绑 `selectedMoistureDate`（store 里字段已经有了）。不加的话，`initSelection` 会一直选 **日期字符串最大** 的那一天，旧图答辩时选不出来。

点图查墒情仍走监测点数字，换热力图不会自动改查询结果。

## 六、地 / 天若组员交的是「图」而不是表

现成 Tab **不会**把 jpg 当底图。可选：

| 做法 | 适用 | 工作量 |
|------|------|--------|
| 把每日数字填进 `sensorReadings` / `weatherForecast` | 与当前折线、预报一致 | 小，**推荐** |
| 另做「产品图册」页或弹窗 `<img>` | 答辩要展示制图成果 | 新 UI，不走 Leaflet |
| 硬接到 GIS/NDVI | 会和地块、对比、查墒搅在一起 | **不推荐** |

不要把气象海报的 `imageAsset` 写进 `ndviLayers`。

---

## 七、容易踩的坑

1. **只改 json、不改 `REMOTE_SENSING_ASSETS`** → 新名字落到默认 NDVI，以为没换图。  
2. **雄县/栾城仍写 `ndvi-heatmap`** → 和河间同一张图，换地块只是框挪了。  
3. **日期格式** 必须 `YYYY-MM-DD`，和控件、排序一致。  
4. **对比** 两期 `bounds` 应相同（都用该地块框），否则叠图错位。  
5. **忘了 `sync:mock-db`** → 本地 Mock 对了、部署包不对。  
6. **图片过大** → 首次切 Tab 卡顿。先压成 webp。  
7. GIS 多日期却不加选择器 → 只能看到最新一天。
