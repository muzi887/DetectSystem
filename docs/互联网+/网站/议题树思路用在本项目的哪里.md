# 议题树思路用在本项目的哪里

> 面向「书看懂了、对上项目就晕」的读者。  
> 书里的案例是 Acme 装饰品公司怎么涨销量。本文只做一件事：把同一套问法，翻译成 DetectSystem 里你已经在做的模块。

---

## 一、先忘掉那棵树，只记三句话

书里教的不是画图，是一种**开工顺序**：

1. 先写下你现在相信的解题办法（叫**初始假设**）
2. 再把每条办法拆成几个必须回答的小问题（叫**议题**）
3. 每个小问题都要能用数据或实验证明「对」或「错」，不要先堆功能

装饰品公司的大问题是「怎样增加销量」。  
本项目的大问题是：**怎样让拍一张叶子照片之后，系统能帮人早点发现灾害、预警别乱报、防治建议能照着做。**

规划文档里的原话是「早发现、准预警、精防治」。下面整篇都围着这一句拆。

---

## 二、书里的三层，对上本项目是什么

书里那张图从左到右是：

```text
增加装饰品销量
    ├── 改变销售方式
    ├── 改进营销方式
    └── 降低单位成本
```

换成我们的系统，左右对齐看：

| 书里 | 本项目 | 人话 |
|------|--------|------|
| 增加装饰品销量 | 早发现、准预警、精防治 | 我们到底要达成什么 |
| 改变销售方式 | 把病认准、认错能收回来 | 货（识别结果）怎么交到用户手里 |
| 改进营销方式 | 把防治建议说清楚 | 用户看完知不知道下一步做什么 |
| 降低单位成本 | 预警别漏、也别乱报 | 少做无用功，少耽误农时 |

再往下拆一层，就是你仓库里已经有的东西：

```text
早发现、准预警、精防治
│
├── 1. 把病认准
│     智能分析页上传照片
│     Flask 推理（ml-bjj/serving）
│     用户纠错写入 hard_cases
│
├── 2. 把建议说清楚
│     treatments.json 防治库
│     智慧决策页右侧「AI 建议」
│     P3 拼出来的一句适期 advice
│
└── 3. 预警既及时又不太吵
      预警中心
      环境灾害规则链（墒情、高温）
      P3：病名 × 空气湿度/气温/土壤湿度
```

读到这里你只需要记住：**左边是目标，右边三根是三条还没被完全证明的路。** 不是「功能菜单」，是「我们猜这三件事做对了，目标就能达成」。

## 三、为什么说「还没被证明」

书里反复强调：假设不是答案。几个月后它可能出现在汇报首页；也可能被数据推翻，但推翻的过程会告诉你下一步该走哪。

本项目里最容易把「已经写进计划的规则」误当成「已经正确的答案」。例如 P3 计划里写死了：

- 稻瘟病 / 稻颈瘟 / 小麦赤霉病，空气湿度 ≥ 80% → 预警至少升到 high
- 土壤体积含水率 ≤ 15% → 至少升到 medium
- 气温 ≥ 38℃ → 至少升到 high

这些数字**现在就该按计划写成代码**（工程上不要再争论）。  
但它们在书里的身份，和「销售人员应该按顾客类型而不是按地区来分」是同一类东西：**先这么干，再用真实识别记录去检验。**

## 四、现在真正用得上的三处（按你正在做的文档）

下面每一处都用同一张小卡片：**假设是什么 → 对应哪个文件/页面 → 怎样算证明对了 → 怎样算证明错了。**

### 4.1 P2：识别记录和纠错（先把证据留下来）

**假设：** 模型大体认得准；认不准时，用户会改标签，我们能把错图收回来再训练。

**对应：**

| 你看到的名字 | 实际位置 |
|--------------|----------|
| 识别记录 | `ml-bjj/serving/analysis_store.py`，文件 `analysis_records.json` |
| 纠错回流 | `POST /api/analysis/feedback` → `ml-bjj/data/hard_cases/pending/<正确病名>/` |
| 计划文档 | `新模型训后-P2-闭环与数据实施计划.md` |

**怎样证明对了：** 记录能按病名统计；低置信度会标 `needs_review`；用户改正后，图出现在对应病名的 `hard_cases` 文件夹里。

**怎样证明错了：** 纠错几乎没人用；或者错几乎全堆在某两三个病名上（例如玉米锈病和玉米南方锈病总被搞混）。那就不是「再加一个页面」能解决的，而是下一轮训练要专攻这些难例。

书里那句「假设错了也没关系，证伪过程已经给了足够信息」，在本项目里指的就是这个文件夹：`hard_cases` 不是垃圾桶，是「假设错了以后的地图」。

### 4.2 P3：病名乘上气象（先按计划实现，再拿记录检验）

**假设：** 同一种病，碰上高湿 / 干旱 / 高温，危险程度应该比「只看照片」更高，所以要升降预警级别，并补一句适期建议。

**对应：**

| 你看到的名字 | 实际位置 |
|--------------|----------|
| 规则函数 | 计划中的 `ml-bjj/serving/disease_env_rules.py` |
| 气象读数 | 监测点的 `airTemp`、`airRh`、`soilVwc`（可从请求带入，或按 `pointId` 去 Mock 拉） |
| 计划文档 | `新模型训后-P3-规则链与工程化实施计划.md` |

**怎样证明对了（P3 做完、有一批真实记录之后）：** 高湿时的稻瘟确实常被标成高风险，而且用户没有大批量把它们改回「健康」。

**怎样证明错了：** 系统天天因「湿度 80%」把级别拉满，但照片是健康叶、用户也在纠错里改成健康。那就改阈值或缩小病名单，而不是再新写十条规则。

这一步很像书里的「东北超市卖得好，能不能推广到全国」：先有一条可执行的假设，再切开数据看它站不站得住。

### 4.3 智慧决策页和防治库（建议必须能照着做）

**假设：** 用户不是要一篇百科，而是要知道「打不打药、浇不浇水、什么时候做」。

**对应：**

| 你看到的名字 | 实际位置 |
|--------------|----------|
| 防治条目 | `ml-bjj/knowledge/treatments.json`（字段里的 `timing` 是适期） |
| 决策页 | `/decision`，`DecisionSupport.vue` 右侧建议栏 |
| 分析页 | `/analysis`，识别结果旁边的防治说明 |

**怎样证明对了：** 点开一条预警，右侧能在几秒内看出处置动作；23 个病名都能查到自己的条目，不会缺条目时错误显示成「健康」。

**怎样证明错了：** 右侧是一大段症状描述，答辩时评委问「那现在该干什么」答不出来。这和书里「祈祷好天气」一样——听起来像建议，其实没法执行。

## 五、和 2.0 三条规则链的关系（避免和 P3 搞混）

仓库里还有一份更早的方案：`规则链建模与实现方案.md`。那里的「三条链」和上面第 4.2 节不是同一张图，但问法相同。

| 链 | 它猜的是什么 | 数据从哪来 |
|----|----------------|------------|
| 链1 环境灾害 | 实测温湿度/墒情持续越线，就该报旱涝热害 | `weatherReadings` 等 |
| 链2 极端天气 | 未来几天预报里有大风高温等，就该提前报 | 7 日预报 |
| 链3 虫情风险 | 预报 + NDVI + 生育期凑在一起，虫病风险升高 | 遥感 + 阈值配置 |
| P3 病名×环境 | **已经认出某种病之后**，再用当前气象决定要不要升级 | 识别结果 + 该点气象 |

前三条解决「没拍照时，环境自己会不会出事」。  
P3 解决「已经拍照认出病了，要不要把级别再抬一档」。

答辩时可以用同一套结构讲故事：大目标是闭环；三条环境链 + AI 识病是第一层办法；每条下面用误报率、识别准确率、从拍照到预警的时间来证明。

## 六、不要用这套思路的地方

下面这些**已经是约束，不是待证明的假设**，不必再拆议题树：

- 不上 Django / Spring
- 本轮不重训检测模型
- 不改智能分析页三列布局
- ONNX 默认关闭
- Flask 听 5000 端口、Mock 听 3000 端口

页面 CSS 溢出来、代理配错、测试红了，用排查清单即可，不要先画一棵树。

议题树适合：**还有好几条路、每条都要花数据或调研才能知道对不对。**  
不适合：**计划已经写死、按文件改代码就能验收的 Task。**

所以：P2、P3 的 Task 文档继续按步骤做；本文只提醒你「做完之后拿什么来检验当初的猜测」。

## 七、对照书里的检查清单（本项目版）

把装饰品公司的清单换成我们的词：

- [ ] 大问题说成了一句：早发现、准预警、精防治
- [ ] 第一层只有少数几条可执行的路（认准、说清、报得准），不是二十个功能点
- [ ] 每条路都能指到具体文件或页面
- [ ] 每条路都想过「怎样用记录/纠错/误报来证明对错」
- [ ] 证明不了的想法没写进树（例如「模型自己变准」——无法执行）
- [ ] 先把 P2 的记录和纠错做出来，再谈「规则对不对」「要不要再训练」

---

## 八、读完只记这一段

本项目不是缺一棵漂亮的图，而是缺「猜了之后怎么验」。

1. **P2 先留证据**（识别记录 + `hard_cases`）  
2. **P3 按计划把「病名×气象」写成函数**（先当初始假设用）  
3. **有了一批真实记录之后**，再决定是改阈值、补防治文案，还是拿难例去再训练

这和书里「先写假设、再拆议题、再收集事实」是同一件事。树是给后面的研究用的路线图，不是给现在每个 Task 再画一遍的装饰。
